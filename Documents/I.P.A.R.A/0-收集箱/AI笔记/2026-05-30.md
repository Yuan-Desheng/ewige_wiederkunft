## 主题1：MinIO视频上传功能实现（YouTube平台）

### 背景

用户需求：所有平台的图片和视频都需要上传到MinIO，因为平台官方CDN有时间显示，过期了就失效了。

### 原始对话

**用户**：所有平台的图片和视频，都需要上传到minio，平台官方CDN是有时间显示的，过期了就失效了，继续这个未完成的任务

**助手**：我来分析一下YouTube平台的视频上传情况...

**分析发现**：
1. `get_video_info_v2` API 只返回视频元数据（标题、作者、观看数等），**不返回实际视频文件URL**
2. `get_video_streams_v2` API 返回 `formats[]` 和 `adaptive_formats[]` 数组，包含真正的视频文件URL（如 `https://rr5---sn-o097znzr.googlevideo.com/videoplayback?...`）
3. 当前没有spider调用 `get_video_streams_v2` 接口
4. `YouTubeChannelVideoItem` 没有 `video_url` 字段

### 技术方案

**YouTube 与 TikTok/Instagram 的关键区别**：
- TikTok/Instagram：视频URL有签名时效性，过期了就403
- YouTube：视频文件URL是直接CDN链接，**没有时效签名问题**（从示例可见 `expire=1775494735` 是2天后，但这只是CDN缓存，不是签名验证）

### 工作流程

```
youtube_video_detail 爬虫运行 →
  1. get_video_info_v2 → 获取基本信息
  2. get_video_streams_v2 → 获取视频流 URL (video_url)
  3. get_video_info(V1) → 获取点赞数和评论数
  → MinIOImagePipeline 自动将 video_url 视频上传到 MinIO
```

### 基础知识点

1. **MinIO对象存储**：通过SSH隧道连接远程MinIO，用于永久存储媒体文件
2. **YouTube视频流API**：`get_video_streams_v2` 返回 `formats[]` 和 `adaptive_formats[]`，包含实际视频文件CDN链接
3. **视频质量选择策略**：优先选择mp4格式的最高比特率视频
4. **平台CDN签名时效性**：TikTok/Instagram的URL有过期签名，YouTube的CDN链接相对稳定

```bash
# 4. 补充YouTube视频详情（评论数、点赞数、视频URL）
#    会依次调用 get_video_info_v2 → get_video_streams_v2 → get_video_info

#    限制处理数量（如只处理10个）
scrapy crawl youtube_video_detail -a limit=10

#    处理指定视频ID
scrapy crawl youtube_video_detail -a video_id=dQw4w9WgXcQ

#    跳过V1接口（只获取基本信息）
scrapy crawl youtube_video_detail -a skip_v1=true
```
