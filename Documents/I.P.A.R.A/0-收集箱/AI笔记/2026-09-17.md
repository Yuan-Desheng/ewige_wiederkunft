### 会话①｜AE 字符延迟拖尾动画 —— 拒绝破解，原创 CharDelay Animator v1.0

- **领域 / 标识**：学习领域 · After Effects 脚本 · 表达式动画
- **日期范围**：2026-09-17（UTC+8）
- **做了什么**：分析商业 AE 脚本 Nisai Delay Animator 的试用版（jsxbin 编译格式）后，用户最初想解除试用机制拿完整源码；拒绝破解商业授权，改为按 AE 公开机制 clean-room 原创实现同等功能，产出 `CharDelay Animator v1.0`（ScriptUI 面板，约 350 行），并修复首次使用报错。
- **关键结论与决策**：
  - jsxbin（`@JSXBIN@ES@2.0@`）不需要反编译器也能提取字符串（字符对编码），可确认功能面与试用机制位置、确认无遥测——但仅用于调研，不动其授权。
  - **决策：不解除商业脚本授权，原创实现**。核心技术：文本动画器 ×4 + 表达式选择器，`Amount` 按 `textIndex` 逐字符求值，`valueAtTime(time − idx·delay)` 采样图层历史变换；四套 Amount 约定（位置加性 / 缩放 100−A / 旋转加性 / 不透明度 100−A）。
  - 首用报「没有选中的文字图层」：`activeItem` 在焦点不在合成查看器时为 null + 文字图层判定不稳 → 改 `instanceof TextLayer` 优先、`project.selection` 兜底、报错带诊断信息（合成名/选中数/是否文字图层）。
- **改动文件清单**：`CharDelayAnimator.jsx`（仓库根目录，新建）
- **一句话踩坑**：表达式引擎必须 JavaScript（Project Settings）；Range 选择器 End 值各版本 100/1 不一致，要双重兜底。
- **复现篇**：[[Documents/I.P.A.R.A/学习领域/收集/AE 字符延迟拖尾动画脚本|AE 字符延迟拖尾动画脚本]]

### 会话②｜微信/飞书粘贴图片卡死 —— xclip 僵死 + X11 选择协议无失败通知

- **领域 / 标识**：学习领域 · niri · Wayland/X11 剪贴板
- **日期范围**：2026-09-17（UTC+8）
- **做了什么**：排查微信/飞书粘贴任何图片（截图、浏览器复制的图）整体卡死的问题；两次修复未命中后改抓进程证据定位真因，重写加固 `clip-sync-wl-x11` v3，用户确认恢复。
- **关键结论与决策**：
  - 误判①性能：56KB / 5.3MB 复制计时均即时完成，排除吞吐问题 → 转向 `ps aux` 抓到 3 个长时间挂死的 `xclip -o` 进程——「死等」不是「慢」。
  - 真因链：当天按过 `Win+Shift+E`（niri 默认绑定 = `quit` 退出整个会话）→ 会话重启竞态把镜像脚本的 xclip 常驻 fork 打僵 → X11 选择协议**无失败通知**，粘贴请求排队永挂 → 应用冻住。
  - 修复四件套：所有 `xclip -o` 加 timeout；TARGETS 探测超时自愈（清 fork 重镜像）；启动延迟 3s；对比哈希只读前 256K（性能项，仍保留）。
- **改动文件清单**：`~/.local/bin/clip-sync-wl-x11`（重写 v3 加固版）
- **一句话踩坑**：`pkill -f` 会自匹配执行它的 shell 的命令文本（exit 144），要用 `'clip-sync-wl-x1[1]'` 方括号模式且 kill/start 分两步。
- **遗留**：`Mod+Shift+E { quit; }` 高危键位待改绑/删除（config.kdl 约 708 行）。
