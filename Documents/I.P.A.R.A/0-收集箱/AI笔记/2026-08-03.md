### 会话①｜修复 cc-switch / hermes 模型配置（GLM-5-Turbo 报错 + 配置断裂）

- **领域 / 标识**：工作领域 · Hermes Agent · cc-switch · GLM 模型配置
- **日期范围**：2026-08-03（UTC+8）
- **做了什么**：排查 hermes 使用 GLM-5-Turbo 时 `response.content invalid (not a non-empty list)` 报错，修复 cc-switch DB 与 hermes config.yaml 之间的 4 处配置不一致。

#### 报错现象

```
Invalid API response (attempt 1/3): response.content invalid (not a non-empty list)
🏢 Provider: model=glm-5-turbo
📝 Provider message: Unknown
⏱️  fast response (1.5s) — likely rate limited
```

3 次重试全部失败，1.5s 快速返回说明模型没真正处理。

#### 根因分析

**curl 直连测试结论**：GLM Anthropic 端点（`https://open.bigmodel.cn/api/anthropic/v1/messages`）本身完全正常——简单对话、带 tools 的 agentic 请求、streaming 流式，三种全部 200 OK。API key 和端点都没问题。

**根因**：GLM-5-Turbo 是"龙虾任务核心需求专项优化"的裁剪模型。面对 hermes 的超长 system prompt（几千行）+ 几十个 tools 定义时，模型返回空 content 列表 `[]`，hermes 校验 `content` 非空列表失败。这是模型能力限制，不是配置错误或 API 故障。

#### 发现的 4 个配置问题

| # | 问题 | 位置 | 危害 |
|---|------|------|------|
| A | `model.base_url` 指向 MiniMax 但 provider 是 GLM | config.yaml `model:` section | fallback 时发错端点 404 |
| B | GLM-5-Turbo 在 hermes agentic 模式不可用 | config.yaml + cc-switch DB | 触发空 content 报错（用户遇到的） |
| C | DeepSeek provider name 是 UUID，fill_first 写的是另一个名字 | 两处不匹配 | fallback 到 DeepSeek 断链 |
| D | fill_first 链与 custom_providers 名称不对齐 | config.yaml | 同上 |

具体：

**A. base_url 错误**
- config.yaml `model.base_url` = `https://api.minimaxi.com/anthropic`
- 但 `model.provider` = `GLM-glm5`，实际应该是 `https://open.bigmodel.cn/api/anthropic`
- cc-switch DB 里的 custom_providers 配置是对的，只是 config.yaml 的 model.base_url 残留了旧值

**B. GLM-5-Turbo 不可用**
- config.yaml custom_providers 和 cc-switch DB 都有 GLM-glm-5-turbo 条目
- curl 实测简单请求正常，但 agentic 模式（超长 system + 大量 tools）返回空 content

**C. DeepSeek 名称断裂**
- config.yaml 和 cc-switch DB 里 name = `dd6e2c91-9b9a-4e1a-9f23-8d6e1a2b3c4d`（UUID）
- fill_first 链里写的是 `DeepSeek-deepseekv4pro[1m]`
- 两边对不上，fallback 到 DeepSeek 时找不到 provider

**D. fill_first 链断裂**
- `DeepSeek-deepseekv4pro[1m]` 在 custom_providers 里不存在（实际 name 是 UUID）

#### 修复操作

1. `hermes config set model.base_url "https://open.bigmodel.cn/api/anthropic"`
2. Python 脚本删除 config.yaml custom_providers 中的 GLM-glm-5-turbo（7→6 条）
3. Python 脚本删除 cc-switch DB 中 app_type='hermes' 的 GLM-glm-5-turbo 行
4. DeepSeek name 统一为 `DeepSeek-deepseekv4pro`（config.yaml + cc-switch DB + provider_endpoints）
5. fill_first 链 `DeepSeek-deepseekv4pro[1m]` → `DeepSeek-deepseekv4pro`

#### 修复后状态

**config.yaml custom_providers（6 条）：**
- GLM-glm5 → glm-5, bigmodel.cn/api/anthropic
- MiniMax-CN-MiniMaxM2.7 → MiniMax-M2.7, minimaxi.com/anthropic
- GLM-glm4.7 → glm-4.7, bigmodel.cn/api/anthropic
- Kimi-k2.5 → kimi-k2.5, moonshot.cn/anthropic
- DeepSeek-deepseekv4pro → deepseek-v4-pro[1m], deepseek.com/anthropic
- minimax-cn-minimaxm3 → MiniMax-M3, minimaxi.com/anthropic

**fill_first fallback 链：** GLM-glm5 → MiniMax-CN-MiniMaxM2.7 → DeepSeek-deepseekv4pro → GLM-glm4.7

**一致性验证：** cc-switch DB 6 个 hermes provider = config.yaml 6 个 custom_providers，完全一致。fill_first 4 个全部能在 custom_providers 中找到。

#### GLM 官方模型推荐（适合 hermes agentic 模式）

从 https://docs.bigmodel.cn/cn/guide/start/introduction 模型概览查到的文本模型：

| 模型 | 上下文 | 最大输出 | 定位 |
|------|--------|----------|------|
| GLM-5.2 | 1M | 128K | 最新推荐，Coding 开源 SOTA，复杂长程任务 |
| GLM-5.1 | 200K | 128K | Coding 对齐 Claude Opus 4.6 |
| GLM-5 | 200K | 128K | 编程对齐 Claude Opus 4.5，擅长 Agentic（当前默认） |
| GLM-5-Turbo | 200K | 128K | 龙虾任务专项优化（hermes 不可用，已删） |
| GLM-4.7 | 200K | 128K | 通用对话/推理/智能体升级 |
| GLM-4.6 | 200K | 128K | 高级编码/复杂推理/工具调用 |

curl 实测 GLM-5.2 也能正常走 Anthropic 端点。当前 hermes 默认用 GLM-5 正常工作。
