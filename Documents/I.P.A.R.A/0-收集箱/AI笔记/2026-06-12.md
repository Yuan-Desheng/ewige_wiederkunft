**任务**：地市级、区县级页面的行业明细列表支持像省级一样点击跳转到行业详情页（后端 `/industry-detail` 已支持 `city`/`county` 参数）。

**改动（3 个文件）**：

1. `src/api/forecast.ts:328` — `GetIndustryDetailParams` 的 `district` 改为 `county`，并补充可选的 `province`，与后端新签名对齐。
2. `src/pages/forecast/industry/[name].vue` — 调用 `getIndustryDetail` 时将路由 query 的 `district` 映射为接口参数 `county`；同时把 `city`/`district` 透传给 `PowerLoadCurveCard`（该组件已内置 district→county 映射），使负荷曲线与区域上下文一致。
3. `src/pages/forecast/components/IndustryDetailPanel.vue:294` — 移除 `handleRowClick` 中 `apiLevel !== 'province'` 的拦截，三级页面均可点击；`clickable-table` 鼠标手势样式改为恒定生效。跳转 query 携带 `city`/`district`（保留原有去"供电公司"后缀逻辑），面包屑会自动显示「全省 → 市 → 区县 → 行业」路径。

**验证**：
- ESLint 通过。
- typecheck 方面有个环境问题需要说明：`vue-tsc` 不在项目 devDependencies 里，`pnpm typecheck` 依赖 npx 临时下载最新版（3.x），而新版直接拒绝项目旧式 tsconfig（`moduleResolution: node10`），所以该脚本目前在任何机器上都会失败，与本次改动无关。我改用固定版本 vue-tsc 2.0.29 + TS 5.5.4 完成了检查：本次改动的 3 个文件没有引入任何新错误，剩余 82 行报错均为仓库既有问题（如 `route.params.name` 的同款报错在 7 个 `[name].vue` 页面中都存在）。

**1. 行业明细点击跳转：county / district 参数命名陷阱**

- **修改原因**：市/区县级行业列表不能跳转有两个阻碍——前端 `handleRowClick` 里写死了 `apiLevel !== 'province'` 的守卫；更隐蔽的是前端给 `/industry-detail` 传的参数名是 `district`，而后端 Spring `@RequestParam` 定义的是 `county`。HTTP GET 的 query 参数没有 schema 校验，**名字对不上时后端只是拿到 null，不会报错**，属于典型的"静默失败"。
- **基础知识点**：前后端字段命名不一致时，应在 **API 边界做一次映射**（adapter 模式，`county: props.district`），而不是全链路改名——把差异限制在一个文件里。本项目约定：路由/props 用 `district`，仅在调接口时转 `county`。
- **官方文档**：
  - Spring `@RequestParam`：https://docs.spring.io/spring-framework/reference/web/webmvc/mvc-controller/ann-methods/requestparam.html
  - Axios 请求配置 params：https://axios-http.com/zh/docs/req_config

**4. 分值"截断"而非"四舍五入"（0.999999 → 0.99）**

- **修改原因**：`toFixed(2)` 是四舍五入，`0.999999730…` 会显示成 `1.00`——归一化分数被渲染成"满分"，产生误导。用户要求精准展示，改为 `Math.floor(x * 100) / 100` 截断。
- **基础知识点**：

  - 截断 vs 四舍五入是**业务语义**选择：对有上限（1.0）的评分，截断更保守，不会"虚标满分"。本项目 CLAUDE.md 已将"两位小数截断"定为全站数值展示规则（`fmtNum`）；
  - 实现要点：`Math.floor(clamp01(n) * 10 ** d) / 10 ** d`，再 `.toFixed(d)` 补齐尾零（此时数值已截断，toFixed 不会再进位）。
- **官方文档**：
  - https://developer.mozilla.org/zh-CN/docs/Web/JavaScript/Reference/Global_Objects/Number/toFixed

#### 知识点解析（会话二）

**1. ECharts `autoresize` 高度反馈循环（页面高度缓缓增加）**

- **修改原因**：本次最有价值的 bug。两张图表卡片在同一 grid 行内 `align-items: stretch` 互相等高拉伸，而 v-chart 画布在普通文档流中用 `h-full` 撑高度——形成"画布变高 → 行变高 → 另一张卡变高 → 它的画布 autoresize 再变大 → 行再变高"的**每帧爬升循环**。
- **基础知识点**：
  - 根因模式是"**测量结果反过来影响布局，布局又触发测量**"（与 ResizeObserver loop 同类问题）；
  - 修复套路：图表画布 `position: absolute; inset: 0`，外层容器 `position: relative + min-height`——容器高度完全由布局决定，画布只**被动填充**，切断反馈链。这是 ECharts 自适应容器的最佳实践之一；
  - vue-echarts 的 `autoresize` 基于尺寸监听自动 `resize()`，方便但要保证"容器尺寸不依赖画布"。
- **官方文档**：
  - vue-echarts：https://github.com/ecomfe/vue-echarts
  - MDN ResizeObserver：https://developer.mozilla.org/zh-CN/docs/Web/API/ResizeObserver

**2. 韦恩图半径自适应 + 数值定位改"网格采样质心"**

- **修改原因**：① 圆半径基数写死 105px，三圆纵向跨度约 290px 超出 240px 容器——改为用 VueUse `useElementSize` 监听容器，半径按容器宽高计算；② 7 个区域数值原用几何启发式（圆心连线中点）定位，三圆半径不等时会落进相邻区域——改为对画布做 72×72 网格采样、按"点属于哪些圆"判定归属区域，取**真实区域的质心**（质心落在区域外时回退最近采样点）。
- **基础知识点**：写死的几何位置在动态数据下总会再错位；采样求质心是"一劳永逸"的通用解法（区域不规则、解析解难求时，用离散采样近似）。
