### 检索库 Meilisearch 重构 + 生产事故（overseas-sentiment / 2026-07-13）

**做了什么**：把海外舆情系统「检索库」从多个 `LIKE %kw%` 前端拼盘，重建为 Meilisearch 驱动的聚合检索（全字段全文 + 人物/帖子/事件三类 + 左侧 facet + 传统分页）。全程走 brainstorm → spec → plan → 12 个 TDD task（subagent 逐个实现+复审），再上生产部署。

**关键结论与决策**：
- 选型 Meilisearch（非 ES/MySQL fulltext）：万级数据 + 单机 ECS + 多语言 + 要 facet 的甜区。
- 三个 typed index（persons/posts/events），`total` 取真实 `estimatedTotalHits` 之和；时间筛选对人物不生效；仅重建 web 前台。
- 本期只做全量重建 + 手动 rebuild 端点，不做增量同步。
- 部署走 `docker-compose.override.yml` 叠加，不动原 compose。

**改动文件**：后端 `framework/search/*`（config/core）、`service/search/*`、`SearchController`、`PortalSearchResultVO`、两个 pom；前端 `searchLibraryList/{index,searchParams,components/*}`、`api/postinfo`。commit 分布在 backend-server(`master-jdk17-prod`) 与 web(`master`)。

**一句话踩坑**：Meili 报错时 `getMessage()` 的 NPE 在 catch 块里二次抛出、拖垮 Spring 启动导致生产崩溃循环——降级路径里的日志本身绝不能再抛异常；另镜像源 `meilisearch:latest` 是 2021 古董 v0.24、与新 SDK 不兼容，须钉 v1.x。
