#### 会话 25ba4ab3（06-18 12:08~16:45）

- **做了什么**：用 `01-prototypes/prototype V6` 高保真原型重绘仿真预测页面，把 `src/pages/simulator/index.vue` 从旧调度模型整体重写为「可调能力缺口驱动评估」五步向导（数据层纯函数 + 5 步 UI + store/api），随后把页面组件统一替换为项目既有 Element Plus 组件，并做主题色/明暗/单位/滑条/进度环等样式打磨。
- **关键结论 / 决策**：
  - 数据层做成可单测纯函数（固定随机种子 20260617 → 幂等可复现）；UI 与实时预览共用同一引擎 `evaluate()` 作为单一真相源。
  - EP 无对应物的定制视觉（Hero/仪表盘/步进器/流式日志/图表/进度环）保留自绘，其余表单/表格/按钮/提示全换 EP。
  - EP 主题色用 `html:root` 覆盖品牌色（特异性胜过 EP 默认 `:root`，免 `!important`）；深色模式必须显式 import `element-plus/theme-chalk/dark/css-vars.css`。
  - 计算执行去掉读秒自动跳转，改为完成后弹 `el-dialog` 由用户点击跳转；功率单位统一「万千瓦」。
- **改动文件**（去重）：`src/pages/simulator/index.vue`、`types.ts`、`composables/{useMockUsers,useValuationEngine,useSimResult,useSimWizard,useMockHistory,useReportExport}.ts` + 引擎单测、`components/{StepNav,OverviewPanel,step1/ParamConfig,step1/ConfigPreview,step2/ExecutionPanel,step3/ResultOverview,step3/UserDetailTable,step4/StrategyReport,step5/HistoryPanel}.vue`、`stores/simulator.ts`、`api/simulator.ts`、`main.ts`、`styles/main.css`。
- **踩坑**：进度环"方框"连环坑根因是类名 `ring` 撞 UnoCSS `ring` 工具类（注入蓝色 box-shadow）→ 改名 `prog-ring`；EP 深色不生效是没 import `dark/css-vars.css`；`el-slider` 黑菱形 tooltip 需全局 `tooltip-class` 染色；后台 build 假阳性 exit 1（timeout 包装器/`grep -c` 零匹配），看真实退出码。

#### 会话 e99fd68f（06-18 17:03~18:32）

- **做了什么**：(1) AiSummaryCard 的【本周】【本月】文案最前面补"平均负荷"；(2) 修复电力负荷曲线切短期/超短期时，曲线刷新但「实时负荷」「当日最高负荷」KPI 卡片不联动、数字不一致；(3) 24 小时负荷热力图横轴刻度过密。
- **关键结论 / 决策**：卡片不刷新的根因是**数据源相互独立**——KPI 卡取自 `core-data` 预计算接口（与预测时长无关），曲线取自 `load-prediction` 接口（最后一个实际点会随 4h/24h 切换变化），切 tab 只重拉曲线、不重算卡片。方案「曲线为准、卡片同步」：曲线把最新/最高实际负荷发布到共享 store，卡片读取覆盖，且**仅 24h 范围生效**（7d/30d 首卡是平均负荷，覆盖会污染）。
- **改动文件**：`src/stores/kpi.ts`（新增 `curveLatestLoad`/`curveMaxLoad` + setter）、`PowerLoadCurveCard.vue`（拉曲线后 `publishCurveStats()`、卸载清空）、`KpiSectionRows.vue`（24h 用 store 覆盖卡片）、`AiSummaryCard.vue`（7d/30d 段首加平均负荷）、`CityErrorCompareCard.vue`（热力图横轴 `interval` 3→11 + `hideOverlap`）。
- **踩坑**：7d/30d 首卡是平均负荷而非实时负荷，覆盖必须限定 24h；city/district 复用同组件，改动一并生效；共享 store ref 需确认同页只挂载一个曲线实例（各页 `onUnmounted` 清空）。
- **知识点**：跨组件共享派生状态用 Pinia store 做单一数据源 + setter 发布，比组件互传更适合「一处算、多处读」联动（[Pinia State](https://pinia.vuejs.org/core-concepts/state.html)）；组件卸载用 `onUnmounted` 重置共享 ref 避免残留（[Vue onUnmounted](https://cn.vuejs.org/api/composition-api-lifecycle.html#onunmounted)）。
