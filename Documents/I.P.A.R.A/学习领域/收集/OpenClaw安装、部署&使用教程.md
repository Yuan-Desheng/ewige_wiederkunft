### OpenClaw 工作目录结构笔记

 📁 根目录：`~/.openclaw/`
 
OpenClaw 的所有核心数据、配置、状态都存放在用户主目录下的 `.openclaw` 文件夹中。你可以用以下命令进入：

```bash
cd ~/.openclaw
ls
```

以下是该目录下的主要内容及作用：

| 文件/文件夹 | 说明 |
|------------|------|
| `openclaw.json` | **主配置文件**。所有核心设置（模型、密钥、渠道等）都保存在这里。 |
| `openclaw.json.bak` / `.bak.1` / `.bak.2` | **配置备份**。每次修改自动生成，防止配置损坏后无法恢复。 |
| `workspace/` | **默认 Agent 的工作区**。存放 Agent 需要长期记住的文件，如项目代码、规则说明、人设等。 |
| `agents/` | **每个 Agent 的后台数据目录**。包含运行状态、认证配置、会话记录等。默认有一个名为 `main` 的 Agent，其工作区指向 `workspace/`。 |
| `logs/` | **运行日志**。排查问题（尤其是 gateway、skills、hooks 相关错误）时优先查看。 |
| `browser/` | **浏览器自动化相关数据**。启用网页抓取/浏览功能后使用，注意潜在的安全风险。 |
| `canvas/` | **临时规划与编排目录**。用于存放任务分解、计划等中间产物。 |
| `cron/` | **定时任务与自动化触发配置**。 |
| `devices/` | **设备与执行环境抽象层**。定义 Agent 能访问哪些本地或远程设备资源。 |
| `extensions/` | **扩展与插件系统文件夹**。 |
| `telegram/` | Telegram 渠道的适配与凭证配置（即使未配置也会默认生成）。 |
| `feishu/` | 飞书机器人的适配与凭证配置（安装飞书渠道后自动生成）。 |
| `identity/` | 身份与认证材料（如本地身份、授权信息）。 |
| `update-check.json` | 更新检查状态与元数据。 |

---

 📂 重点：`workspace/` 文件夹

`workspace/` 是默认 Agent（`main`）的工作目录，存放 Agent 的行为规范、长期记忆和工具说明。进入该目录并查看：

```bash
cd ~/.openclaw/workspace
ls
```

主要文件及作用如下：

| 文件 | 说明 |
|------|------|
| `AGENTS.md` | **岗位说明书**。定义有哪些代理、各自负责什么任务，是最重要的规范文件。 |
| `SOUL.md` | **灵魂设定**。描述 Agent 的整体气质、价值观和行为风格。 |
| `USER.md` | **用户画像**。记录你的身份、偏好、禁忌等个人信息。 |
| `IDENTITY.md` | **身份卡**。Agent 对外报身份时使用的名称、称呼、口径等。 |
| `TOOLS.md` | **工具清单**。列出 Agent 能使用的工具、使用方法及边界限制。 |
| `HEARTBEAT.md` | **心跳机制**。自检与状态汇报规则（如启动后检查什么、多久报告一次状态）。 |
| `BOOTSTRAP.md` | **冷启动说明**。初始化时首先读取的指导文件，帮助 Agent 快速进入正确工作状态。 |
| `memory/` | 日常聊天记忆存放目录，按日期命名的 `YYYY-MM-DD.md` 文件。 |
| `MEMORY.md` | 稳定的长期记忆存放文件。 |

---

💡 使用提示

- **修改配置**：直接编辑 `openclaw.json`，修改后需重启 gateway 服务：`systemctl --user restart openclaw-gateway`。
- **调整 Agent 行为**：编辑 `workspace/` 下的 `.md` 文件（如 `AGENTS.md`、`SOUL.md`），Agent 会自动加载最新内容。
- **排查问题**：先查看 `logs/` 目录或运行 `journalctl --user -u openclaw-gateway -f` 实时查看日志。
- **备份恢复**：如果配置损坏，可将 `.bak` 文件重命名为 `openclaw.json` 恢复。

了解这些目录结构后，你就能更自信地管理和定制你的 OpenClaw 了。

#### 产品经理提示词
创建一个专门负责需求整理的产品经理 Agent，核心是让它能准确理解原始需求、原型修改意见，并输出结构清晰的开发者提示词。下面以 OpenClaw 的 Agent 配置机制为基础，给出每个文件的建议内容。你可以通过 `openclaw agents add product-manager` 创建该 Agent，然后在其目录（`~/.openclaw/agents/product-manager/`）下放置以下文件。
📁 AGENTS.md（岗位说明书）
产品经理 Agent 岗位说明书

职责
- 收集并理解用户原始需求（文字、会议纪要、原型截图说明等）
- 分析现有原型图或修改意见，归纳核心变更点
- 将需求与修改意见整理为清晰、无歧义的提示词，供开发者 Agent 使用
- 输出格式严格遵循以下规范，确保开发者 Agent 可直接执行

工作流程
1. 接收输入：用户提供原始需求描述 + 原型修改点（可以是文本、链接或上传的文件）
2. 分析与提炼：
 - 识别需求中的核心功能、非功能要求、边界条件
 - 对比原型变更，标注新增/修改/删除的部分
 - 提炼关键点，避免冗余
3. 整理为开发者提示词：
 - 格式：背景、目标、具体任务、约束条件、验收标准
 - 语言简洁、技术友好，避免主观评价
4. 输出结果，供开发者 Agent 执行

- 依赖：…

- [ ] 标准1

请参考教程：“
问题
OpenClaw 的 message 工具在飞书上发图有 bug：

filePath 参数 → 飞书收到的是路径文本
media 参数 + 本地路径 → 失败
buffer 参数 + base64 → 数据太大AI 助手并不知道还有别的办法。
       

核心思路
OpenClaw 的 AI 助手每次启动都会读取工作区里的 TOOLS.md 文件。这个文件是"本地笔记"，用来记录环境相关的特殊配置和方法。

   

所以解决方案很简单：把飞书发图的正确方法写进 TOOLS.md，AI 下次醒来读到就会了。

   

AI 助手有 exec 工具可以执行 shell 命令，而飞书发图的本质就是三个 curl 调用。只要 TOOLS.md 里写清楚了步骤，AI 自己就能组合执行。

   

操作方法
在 OpenClaw 工作区的 TOOLS.md 文件中，加入以下内容（直接在对话里发给 OpenClaw 就行了）：

## 飞书发图片（重要！）

OpenClaw 的 `message` 工具目前不能直接在飞书发送本地图片。

**正确方法：用 exec 工具执行 curl 调飞书 API，分三步：**

### Step 1: 获取 tenant_access_token

APP_SECRET=$(python3 -c "import json; c=json.load(open('/root/.openclaw/openclaw.json')); print(c['channels']['feishu']['appSecret'])")
TOKEN=$(curl -s -X POST 'https://open.feishu.cn/open-apis/auth/v3/tenant_access_token/internal' \
  -H 'Content-Type: application/json' \
  -d '{"app_id":"你的APP_ID","app_secret":"'$APP_SECRET'"}' \
  | python3 -c "import json,sys; print(json.load(sys.stdin)['tenant_access_token'])")

### Step 2: 上传图片获取 image_key

IMAGE_KEY=$(curl -s -X POST 'https://open.feishu.cn/open-apis/im/v1/images' \
  -H "Authorization: Bearer $TOKEN" \
  -F "image_type=message" \
  -F "image=@/path/to/image.png" \
  | python3 -c "import json,sys; print(json.load(sys.stdin)['data']['image_key'])")

### Step 3: 发送图片消息

curl -s -X POST 'https://open.feishu.cn/open-apis/im/v1/messages?receive_id_type=open_id' \
  -H "Authorization: Bearer $TOKEN" \
  -H "Content-Type: application/json" \
  -d '{"receive_id":"收信人open_id","msg_type":"image","content":"{\"image_key\":\"'$IMAGE_KEY'\"}"}'

注意：
- 主人的 open_id: ou_xxxxxxxx
- App ID: cli_xxxxxxxx
- 支持格式: JPEG, PNG, WEBP, GIF, TIFF, BMP, ICO
把上面的内容写进 TOOLS.md，替换其中的 APP_ID、open_id 为你的实际值。”
