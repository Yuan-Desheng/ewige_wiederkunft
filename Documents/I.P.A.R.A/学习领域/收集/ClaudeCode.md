## 重要命令
- /init
	Claude 中的 `/init` 命令，是在终端里启动 **Claude Code**（AI 编程助手）时的一个快捷指令。

简单来说，它的作用是**让 AI 快速“入职”一个新项目**，避免每次对话都需要重复解释项目的基本信息，能节省高达 **80%** 重复设置上下文的时间[reference:0][reference:1]。

### ✍️ `/init` 的核心作用

运行 `/init` 命令，本质上是在为 Claude 建立一个能**长期记忆**的项目知识库[reference:2][reference:3]：

*   **自动生成“说明书”**：它会自动扫描你整个项目的代码库，包括文件夹结构、依赖包、现有文档等[reference:4]，并在项目根目录下生成一个名为 `CLAUDE.md` 的文件[reference:5]。
*   **充当“永久记忆”**：这个 `CLAUDE.md` 文件就像一个**项目说明书**或**记忆档案**[reference:6]，记录了项目的技术栈、架构模式、代码规范等关键信息[reference:7][reference:8]。
*   **提高协作效率**：在后续的每次会话中，Claude Code 都会自动读取这个文件[reference:9]，从而能基于整个项目的真实语境来理解你的问题并提供帮助[reference:10]。

### ⚡ `/init` 的核心价值

1.  **统一项目认知**：让 AI 从一开始就理解项目的构建命令、代码风格和约定，提供的帮助会更准确、更符合项目规范[reference:11][reference:12]。
2.  **减少重复沟通**：你不需要每次都在对话中反复提醒“我们用的是 React 18”或“请遵循 ESLint 规则”这类基本信息。
3.  **提升开发效率**：Claude Code 能更快地理解你的需求，从而提供更精准的代码建议和解决方案。

简而言之，**`/init` 就是你在新项目中使用 Claude Code 时，应该输入的第一个命令**[reference:13]。



/compach
`/compact` 是 Claude Code 里非常核心的一个“上下文管理”命令。你可以把它想象成一个**“智能笔记员”**，当一个复杂的编程对话已经进行了很长时间，信息多到 AI 都开始“记不清”时，你可以让它帮忙，**把之前冗长的对话浓缩成一份精华摘要，然后扔掉所有啰嗦的原始记录，只拿着这份摘要继续工作**[reference:0]。这样不仅能省下大量 Token，还能让 AI 始终专注于核心任务，避免“失忆”[reference:1]。

### 🧠 为什么需要手动压缩？

Claude Code 虽然有一个 20 万 Token 的上下文窗口，看起来很大，但实际可用作对话的只有 **~11.4 万 Token**[reference:2]。一个复杂的调试会话可能会快速消耗掉这些资源，导致 AI 遗忘早期指令、注意力下降[reference:3]。

虽然 Claude Code 也有自动压缩功能，但它的触发点非常靠后（通常是上下文使用率达到 **95%** 时）[reference:4][reference:5]，而且没有针对性，可能会在你工作时突然打断，并丢失关键细节[reference:6][reference:7]。

因此，更专业的做法是**在上下文使用率达到 70%-80% 时，就主动执行 `/compact`**[reference:8][reference:9]。

### ⚙️ `/compact` 具体做了什么？

当你输入 `/compact`，Claude Code 会立刻执行一个三步走的清理流程[reference:10][reference:11]：
1.  **清理“杂物”**：首先，它会删除大量的“过程数据”，比如旧的 `grep`、`ls`、`cat` 等命令的输出结果。这些信息通常最占地方，但对当前任务已经没什么用了[reference:12]。
2.  **提取“精华”**：接着，它会分析整个对话，智能地提取出关键信息，例如：**已完成的工作、正在进行的工作、修改过的文件路径、以及重要的决策和计划**[reference:13]。
3.  **全新开始**：最后，它会将这份结构清晰的摘要加载为新的上下文，并从磁盘重新加载 `CLAUDE.md` 项目指令，让你带着一个“轻装上阵”的 AI 继续工作[reference:14]。

### 📝 如何使用 `/compact`？

1.  **基础用法**：直接输入 `/compact`，让 Claude 自己决定保留哪些关键信息。这在大多数情况下都足够用了[reference:15]。
2.  **进阶用法（带指令压缩）**：在 `/compact` 后加上你的具体要求，让压缩更有针对性[reference:16]。例如：
    *   `/compact 只保留关于 auth 模块的修改和测试结果`
    *   `/compact 保留所有架构决策和待办事项`
    *   `/compact 重点保留 API 接口定义和数据库 Schema 变更`

### 🔄 `/compact` vs. `/clear`

这两个命令容易混淆，但它们的目标完全不同。可以参考这个简单的对比：

| 特性 | `/compact` | `/clear` |
| :--- | :--- | :--- |
| **核心操作** | 将历史对话**压缩成摘要**[reference:17] | **彻底清空**所有历史对话[reference:18] |
| **保留内容** | 保留压缩后的摘要、项目规则（`CLAUDE.md`）[reference:19] | 什么都不保留，一切归零[reference:20] |
| **使用场景** | **任务进行中**，需要释放空间但不想丢失进度[reference:21] | **任务彻底完成**后，或要切换到全新不相关的任务[reference:22] |
| **Token 消耗** | 摘要仍会消耗一部分 Token（例如 ~2K）[reference:23] | 几乎不消耗，为你腾出完整的上下文窗口[reference:24] |
| **历史记录** | 原始的完整对话历史仍保存在本地[reference:25] | 当前会话历史被删除，但可通过 `--resume` 恢复之前的会话 |

### 💡 进阶提示

1.  **定期检查上下文用量**：养成使用 `/context` 命令的习惯，它可以用可视化图表展示当前的上下文占用情况，帮你判断是否需要进行压缩[reference:26]。
2.  **依赖持久化记忆**：记住，`/compact` 压缩后，AI 会重新加载 `CLAUDE.md` 文件[reference:27]。因此，**把那些每次对话都必须遵守的硬性规则、项目约定写入 `CLAUDE.md`，而不是只在对话里口头强调**[reference:28]。这些写在文件里的规则，才是 AI 永远不会“忘记”的长期记忆。

### 💎 总结

总之，`/compact` 就是你在 Claude Code 里进行长时间、复杂任务时的“**进度保存器**”和“**内存清理大师**”。善用这个命令，能让你的 AI 编程助手在长会话中始终保持高效、专注，避免因上下文过载而“精神错乱”。
