## 一、开机：每次重启手机后要做的事

K60 重启后 chroot 和 sshd 都不会自动拉起（Termux:Boot 自启是遗留待办），需要手动启动一次：

1. 手机打开 **Termux**，执行：

```bash
su -c sh /data/local/start_server.sh
```

2. Magisk 弹出超级用户请求 → 点**允许**（若没弹窗，打开 Magisk → 超级用户 → 手动给 Termux 授权）。
3. 看到 `sshd started` 即成功。此脚本做的事：把 `/dev` `/proc` `/sys` bind-mount 进 `/data/local/linux` → `mkdir /run/sshd` → chroot 启动 sshd（端口 22）。

> 交互式进 chroot 调试用：`su -c sh /data/local/start_linux.sh`（进去是 Ubuntu 的 bash，`exit` 退出）。

## 二、从笔记本连接（两种方式）

### 2.1 USB 连接（校园网首选，最稳）

**为什么校园网优先 USB**：校园 WiFi（10.14.0.0/16）普遍开 AP 隔离，手机↔电脑同网段也 ping 不通，SSH 直连会失败；USB 不受影响。

```bash
# 1. 手机插 USB（USB 调试需开启），确认设备（首次插需在手机上点"允许USB调试"）
adb devices

# 2. 把笔记本 2222 端口转发到手机 22 端口
adb forward tcp:2222 tcp:22

# 3. SSH 连接（密码【已脱敏】）
ssh -p 2222 root@127.0.0.1

# 传文件（注意 scp 用大写 -P）
scp -P 2222 本地文件 root@127.0.0.1:/root/
```

> adb 转发在拔线/adb 重启后失效，重连时重新执行 `adb forward` 即可。

### 2.2 WiFi 直连（家庭路由器环境）

1. 手机连上 WiFi → 设置里看当前 IP（如 `192.168.x.x`；IP 会变，建议在路由器上给手机做 DHCP 静态绑定）。
2. 笔记本执行 `ssh root@<手机IP>`。
3. **免密登录**（推荐做一次）：

```bash
ssh-keygen -t ed25519                  # 笔记本没有密钥时
ssh-copy-id -p 2222 root@127.0.0.1     # USB 场景；WiFi 场景去掉 -p 2222 换手机IP
```

### 2.3 SSH config 别名（可选，顺手）

笔记本 `~/.ssh/config` 加一段，之后 `ssh k60` 即可：

```text
Host k60-usb
    HostName 127.0.0.1
    Port 2222
    User root
```

## 三、在手机上跑 Claude Code

ssh 进去后就是 Ubuntu 22.04 + node v20.19.0 + claude-code（装在 chroot 内，prefix=/usr/local）：

```bash
claude --version     # 验证
cd /root && claude   # 启动
```

### Claude Code 联网代理（✅ 2026-10-07 已配置并验证，遗留待办①完成）

Anthropic API / 中转 API 在手机网络下可能直连不通，需要代理。**笔记本的 Clash 只监听 127.0.0.1:7890**，手机够不着，两个方案：

**方案 A：USB + adb reverse（推荐，零配置改动）**。让手机的 `127.0.0.1:7890` 反向通到笔记本的 Clash：

```bash
# 笔记本执行（USB 连接状态下）
adb reverse tcp:7890 tcp:7890

# 然后在手机 chroot 内（ssh 进去后）验证 + 使用
curl -x http://127.0.0.1:7890 -sI https://api.anthropic.com | head -1
export HTTPS_PROXY=http://127.0.0.1:7890 HTTP_PROXY=http://127.0.0.1:7890
claude
```

**此方案已于 2026-10-07 部署到手机**：chroot 的 `/root/.bashrc` 末尾有自动检测段——交互登录时代码探测 `127.0.0.1:7890` 是否可达（即 adb reverse 是否在），在线才 `export` 代理并提示 `[k60] proxy ON`，离线不干扰。所以日常只需：**插 USB → 重跑 `adb reverse tcp:7890 tcp:7890` → ssh 进去直接用**（拔线后 reverse 失效，重插要重跑这一条）。

**方案 B：WiFi + Clash 开局域网访问**。改 Clash 配置 `allow-lan: true`（并放行防火墙 `sudo ufw allow from 10.14.0.0/16 to any port 7890`），手机上 `export HTTPS_PROXY=http://10.14.104.13:7890`。⚠️ 校园网 AP 隔离下大概率不通，且局域网代理有被蹭用风险，仅家庭网络建议。

若使用 API 中转（`ANTHROPIC_BASE_URL` / `ANTHROPIC_AUTH_TOKEN`），同样写进 chroot 的 `/root/.bashrc`。

## 四、保活：不做这步 = 后台被杀，SSH 莫名断开

1. **Termux wake-lock**：Termux 里执行一次 `termux-wake-lock`（通知栏出现 Termux 常驻通知即生效）。✅ 2026-10-07 已开启（`dumpsys power` 确认 `termux:service-wakelock` ACQ）。
2. **MIUI 省电白名单**（❗唯一剩余手动项）：设置 → 应用设置 → 应用管理 → Termux → 省电策略 → **无限制**；再把 Termux 加入电池优化的"不限制"名单。
3. **锁屏测试**：锁屏 10 分钟后再 SSH，确认不断。
4. Magisk → 超级用户 → Termux 设为**自动允许**（可选，省去每次弹窗）。

## 六、故障排查

| 现象 | 原因 | 解决 |
|---|---|---|
| `ssh` 连不上（USB） | sshd 没起 / adb forward 失效 | 手机上跑一遍 start_server.sh；重新 `adb forward tcp:2222 tcp:22`；`adb devices` 确认在线 |
| `ssh` 连不上（WiFi） | AP 隔离 / 手机 IP 变了 | 换 USB；路由器绑定静态 IP |
| 密码对但被拒 | root 密码未设或改过 | chroot 内 `passwd root` 重设 |
| `claude` 报网络错误 | 没配代理 / adb reverse 掉了 | 见第三节；重插 USB 后重跑 `adb reverse` |
| SSH 用着用着断 | Termux 被系统杀后台 | 第四节保活三件套；`termux-wake-lock` 重开 |
| Magisk 不弹授权框 | Termux 被拒绝过 | Magisk → 超级用户 → Termux → 改为询问/允许 |
| 电脑侧 `adb shell su -c ...` 直接 Permission denied | Magisk 只信任 Termux，对「Shell」请求方静默拒绝（锁屏时更甚） | 提权操作必须走手机上的 Termux；或在 Magisk 里手动给 Shell 授权 |
| 电脑遥控往 Termux `input text` 打字，命令变样 | adb shell 层会拆空格——`input text` 的空格必须写 `%s` | 如 `input text 'su%s-c%ssh%s/data/local/start_server.sh'` |
| 笔记本 `adb devices` 空 | USB 调试关了 / 没点允许弹窗 | 开发者选项开 USB 调试；手机上重新授权 |

## 七、进阶：任意网络可达（Tailscale）

给 chroot 装 Tailscale 后，手机和笔记本同入 tailnet，不在同一 WiFi 也能 `ssh root@< tailscale IP>`。⚠️ 校园网环境注意：本机校园网存在 SNI 阻断，Tailscale 需走代理才能登录/打洞（详见 [[Legion 笔记本网络与 Tailscale]]），手机侧同理。暂未部署，列为可选。
