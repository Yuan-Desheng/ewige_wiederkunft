### /init

`/init` 是 Claude Code 的启动命令，让 AI 快速”入职”一个新项目，避免每次重复解释项目基本信息，节省高达 **80%** 重复设置上下文的时间。

**核心作用**

运行 `/init` 本质上是为 Claude 建立一个能**长期记忆**的项目知识库：

- **自动生成”说明书”**：扫描项目代码库（文件夹结构、依赖包、现有文档等），在项目根目录生成 `CLAUDE.md` 文件
- **充当”永久记忆”**：记录项目的技术栈、架构模式、代码规范等关键信息
- **提高协作效率**：后续会话自动读取该文件，基于真实语境理解问题

**核心价值**

1. **统一项目认知**：让 AI 从一开始就理解项目的构建命令、代码风格和约定
2. **减少重复沟通**：无需每次强调”我们用的是 React 18”等基本信息
3. **提升开发效率**：更快理解需求，提供更精准的代码建议

> 简而言之，**`/init` 是你在新项目中使用 Claude Code 时应该输入的第一个命令**。

### /compact

`/compact` 是 Claude Code 里非常核心的”上下文管理”命令。把冗长的对话浓缩成精华摘要，扔掉原始记录，只拿摘要继续工作。省 Token、避免 AI”失忆”。

**为什么需要手动压缩？**

- Claude Code 有 20 万 Token 上下文窗口，但实际可用作对话的只有 **~11.4 万 Token**
- 复杂调试会话会快速消耗资源，导致 AI 遗忘早期指令、注意力下降
- 自动压缩触发点靠后（上下文使用率 **95%** 时），可能丢失关键细节
- **专业做法：在上下文使用率达到 70%-80% 时，主动执行 `/compact`**

**具体流程**

1. **清理”杂物”**：删除旧的 `grep`、`ls`、`cat` 等命令输出结果
2. **提取”精华”**：提取已完成工作、正在进行工作、修改过的文件路径、重要决策和计划
3. **全新开始**：加载结构清晰的摘要，重新加载 `CLAUDE.md` 项目指令

**使用方法**

- **基础用法**：直接输入 `/compact`，让 Claude 决定保留哪些关键信息
- **进阶用法**：带具体要求，如：
  - `/compact 只保留关于 auth 模块的修改和测试结果`
  - `/compact 保留所有架构决策和待办事项`

**`/compact` vs. `/clear` 对比**

| 特性 | `/compact` | `/clear` |
|------|------------|----------|
| **核心操作** | 将历史对话**压缩成摘要** | **彻底清空**所有历史对话 |
| **保留内容** | 压缩后的摘要、`CLAUDE.md` 规则 | 什么都不保留 |
| **使用场景** | **任务进行中**，需释放空间但不想丢失进度 | **任务彻底完成后**，或切换到全新任务 |
| **Token 消耗** | 摘要消耗一部分 Token（约 ~2K） | 几乎不消耗 |
| **历史记录** | 原始对话保存在本地 | 可通过 `--resume` 恢复 |

**进阶提示**

1. **定期检查上下文用量**：使用 `/context` 命令可视化上下文占用情况
2. **依赖持久化记忆**：`/compact` 压缩后 AI 会重新加载 `CLAUDE.md`。**把硬性规则、项目约定写入 `CLAUDE.md`，而不是只在对话里口头强调**

> `/compact` 是长时间复杂任务中的”**进度保存器**”和”**内存清理大师**”。

### /clear
`/clear` 是 Claude Code 中的一个会话管理命令，作用是**清空当前会话的全部对话历史**，相当于开启一个“全新的对话”。

---

## 🧹 核心功能

| 特性 | 说明 |
|------|------|
| **清除内容** | 清除所有历史消息（包括用户输入和 Claude 的回复） |
| **保留内容** | 保留已修改的代码文件、项目结构、工作目录 |
| **重置状态** | 上下文窗口清空，Claude 不再记得之前的任何对话内容 |
| **即时生效** | 执行后立即回到“初始状态”，可以开始新的对话 |

---

## 📝 使用示例

```bash
# 在 Claude Code 会话中直接输入
/clear
```

执行后，你会看到类似这样的提示：
```
Conversation history cleared. Starting fresh.
```

然后可以继续输入新的问题或任务。

---

## 💡 适用场景

| 场景 | 为什么用 /clear |
|------|----------------|
| **切换任务** | 完成一个功能后，想开始另一个完全不相关的任务，避免上下文干扰 |
| **上下文过大** | 会话太长导致 Token 消耗多、响应变慢，清空后提升性能 |
| **对话跑偏** | 对话陷入循环或 Claude 开始“胡言乱语”，清空后重新开始 |
| **隐私清理** | 会话中包含了敏感信息，清空历史降低泄露风险（但日志文件可能仍存在） |

---

## ⚠️ 注意事项

1. **不可撤销**：`/clear` 会永久删除当前会话的历史，无法恢复。如果需要保留某个历史节点，建议先使用 `claude --resume` 或通过第三方工具（如 `claude-sesh`）备份会话。

2. **不影响代码**：已通过 Edit 工具修改的文件内容不会因为 `/clear` 而回滚。如果你希望撤销代码修改，需要使用 `/rewind` 命令。

3. **不删除会话文件**：清空的是当前运行的会话内存，但该会话的 `.jsonl` 文件仍会保留在 `~/.claude/projects/` 目录下。下次用 `claude -r` 选择该会话时，会看到历史已被清空（或只剩下 `/clear` 后的新内容，取决于实现）。

4. **与 `Ctrl+L` 的区别**：
   - `/clear`：清空**对话历史**，Claude 忘记之前的一切。
   - `Ctrl+L`（或 `clear` 命令）：仅清空**终端屏幕显示**，对话历史依然存在，Claude 仍然记得。

---

## 🔄 与相关命令对比

| 命令 | 作用 | 是否可逆 |
|------|------|----------|
| `/clear` | 清空对话历史 | ❌ 不可逆 |
| `/rewind` | 回退到会话中的某个检查点 | ✅ 可选择不同检查点 |
| `claude -c` | 继续最近一次会话（恢复历史） | N/A（启动新进程） |
| `Ctrl+L` | 清屏（仅视觉） | ✅ 可滚动回看 |

---

## 📌 总结

**`/clear` = “忘掉之前说过的一切，重新开始”**

它是你日常使用 Claude Code 时用来隔离任务、清理上下文、恢复性能的最快捷方式。当你在同一个项目目录下切换多个不相关的开发任务时，养成先敲 `/clear` 的习惯，能有效避免“历史遗留问题”干扰新任务。
