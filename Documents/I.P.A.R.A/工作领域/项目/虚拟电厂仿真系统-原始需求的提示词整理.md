- **参数填写**：在该页面定义采集源名称、协议类型（如 MQTT, Modbus）、连接地址及频率等关键参数。
    

---

### 2. 校验阶段：连接性测试

在保存配置前，必须确保通道畅通，避免无效采集。

- **执行测试**：在编辑页面点击“测试连接”按钮。
    
- **反馈结果**：系统跳转至**测试连接结果**页面（或弹窗），展示当前连接的通断状态、响应时延及错误日志。
    
- **异常处理**：若测试失败，返回编辑页修正；若成功，则完成采集源的最终保存。
    

---

### 3. 运维阶段：状态维护与清理

对已有的采集源进行日常管理。

- **确认删除**：对于不再需要的采集源，用户在管理列表触发删除，系统弹出**确认删除采集源**二次确认框，防止误操作导致数据中断。
    
- **信息变更**：通过**新增编辑采集源**对已有配置进行在线更新。
    

---

### 4. 监控阶段：从宏观到微观

数据开始流入后，进入多层级的监控体系。

- **全局监控**：用户通过导航进入**数据采集监控**页面，查看所有采集通道的在线率、丢包率及整体健康度。
    
- **底层数据穿透**：
    
    - **运行数据视图**：点击具体采集源，进入该视图查看原始报文、实时数值曲线及解析状态。
        
    - **用户行为数据视图**：若该采集源涉及终端交互，可进一步查看用户对设备的调控指令记录。

4. **即时校验**：

我们将错误分为**网络层、协议层、鉴权层和业务层**四个维度，以便用户快速定位问题。

|**错误分类**|**错误代码**|**状态描述 (Technical)**|**用户引导建议 (UX Writing)**|**建议后续操作**|
|---|---|---|---|---|
|**网络层**|`ERR_TIMEOUT`|连接超时 (10s+)|**“握手时间太长了”**<br><br>  <br><br>目标服务器未在规定时间内响应，可能是网络波动或防火墙拦截。|检查网络连接或防火墙设置|
||`ERR_DNS_FAIL`|域名无法解析|**“找不到这个地址”**<br><br>  <br><br>请检查填写的 URL 域名是否正确，或者该地址在当前网络下是否可达。|核对 URL 地址|
|**鉴权层**|`ERR_AUTH_401`|未授权 (Unauthorized)|**“通行证失效了”**<br><br>  <br><br>Access Key 或 Token 校验失败，请检查填写凭证是否过期或输入错误。|重新录入鉴权 Token|
||`ERR_FORBIDDEN`|被拒绝访问|**“访问权限受限”**<br><br>  <br><br>当前账户没有访问该数据源的权限，请联系该平台的管理员。|联系平台管理员|
|**协议层**|`ERR_PROTO_MIS`|协议不匹配|**“语言不通”**<br><br>  <br><br>你选择了 MQTT 协议，但目标地址返回的是 HTTP 报文。请核对协议类型。|切换协议类型|
||`ERR_PAYLOAD`|报文解析失败|**“数据格式看不懂”**<br><br>  <br><br>连接已建立，但返回的数据结构与系统预期不符（例如 JSON 格式错误）。|检查原始报文格式|
|**业务层**|`ERR_LIMIT`|频率超限|**“请求太频繁了”**<br><br>  <br><br>对方平台触发了流量控制。请尝试调大“采集频率”（如从 1s 改为 5s）。|调整采集频率参数|

### 2. UX Writing 设计原则建议

为了让页面更具温情且专业，建议遵循以下文案原则：

- **拒绝冰冷的数字**：不要只写 `Error 500`。应使用 **[状态图标] + [友好标题] + [原因解释] + [行动建议]** 的结构。
    
- **使用“人”的语言**：将“Socket Connection Refused”转化为“服务器拒绝了连接请求”。
    
- **明确性**：如果是必填项没写导致的错误，直接高亮该字段，而不是弹出一个模棱两可的报错。

### 二、 核心参数传递逻辑分析（重点）

在 UI/UX 设计转化为前端开发时，明确“页面之间传了什么参数”是重中之重。以下是该模块中四个最核心的参数传递场景说明：

#### 场景 1：列表页到表单页的“身份传递” (List to Form)

- **路径**：`数据采集管理` 点击“编辑” $\rightarrow$ 跳转 `新增编辑采集源`。
    
- **参数传递逻辑**：
    
    - 当点击“新增”时，参数为空，系统渲染空白表单。
        
    - 当点击某一行数据的“编辑”时，列表页会将该行的 **`源 ID (Source_ID)`** 作为 URL 参数（例如 `?id=1024&mode=edit`）传递给编辑页。
        
    - **目标页展示**：编辑页接收到 `Source_ID` 后，自动向后端拉取该采集源的所有历史配置数据（如已填写的名称、URL、协议类型等），并反显在表单中。
        

#### 场景 2：表单配置到联调反馈的“状态传递” (Form to Feedback)

- **路径**：`新增编辑采集源` 点击“测试连接” $\rightarrow$ `测试连接结果`。
    
- **参数传递逻辑**：
    
    - 用户在表单填写的临时参数（**`URL`**、**`Token`**、**`Protocol`**）被打包作为 Payload 传递给后端进行模拟握手。
        
    - 后端返回握手结果包（包含 **`Status_Code`** 状态码、**`Latency`** 延迟毫秒数、**`Error_Message`** 错误信息）。
        
    - **目标页展示**：结果页根据返回的 `Status_Code` 决定渲染绿色成功 UI 还是红色失败 UI；并将 `Latency` 的值（如 43ms）映射为进度条的长度。
        

#### 场景 3：宏观看板到微观视图的“上下文下钻” (Dashboard Drill-down)

- **路径**：`数据采集监控` $\rightarrow$ `运行数据视图` / `用户行为数据视图`。
    
- **参数传递逻辑**：
    
    - 在监控总览中，如果用户在“过滤器”中选择了特定条件（如：**`Region=杭州市西湖区`**，**`Device_Type=5G基站`**），当用户点击下钻进入明细视图时，这些过滤参数必须通过全局状态 (State) 或 URL 参数被携带过去。
        
    - **目标页展示**：`运行数据视图` 初始化时会读取这些参数，其顶部的筛选框会自动锁定为“杭州市西湖区”和“5G基站”，底部的表格仅渲染符合这些条件的明细数据。
        

#### 场景 4：组件间状态联动的“权重传递” (State Synchronization)

- **路径**：`关联数据源配置` $\rightarrow$ `关联数据管控`。
    
- **参数传递逻辑**：
    
    - 表单中的 **`Priority`** (优先级滑动条，取值 0-100) 和 **`Status`** (启用/禁用开关) 保存后写入数据库。
        
    - **目标页展示**：管控列表页读取这些参数，将 `Priority` 渲染为横向的可视化进度条长度，并将排序逻辑设定为按此参数从高到低排列。

### 三、 给开发者的交互逻辑备注建议

当你在整理这份原型的交互文档给开发团队时，建议补充以下全局级别的逻辑说明：

### 2-9-“资源画像”和“负荷预测”总结
```
这两个模块构成了虚拟电厂（VPP）仿真系统的**“资源分析”与“未来推演”**核心。如果说“资源画像”是确定我们手里有多少兵马，那么“负荷预测”就是推演未来的战场局势。

以下是针对这两个模块逻辑联系及参数传递的深度分析：

---

## 1. 模块间的逻辑架构

这两个模块并非独立运行，而是一个**“属性映射到结果”**的过程。

- **资源画像（静态/属性层）**：定义了资源在地理空间、调节能力和历史表现上的固定标签。
    
- **负荷预测（动态/推演层）**：利用画像中的能力边界，结合外部修正因子，由 AI 智能体组输出未来的负荷曲线。
    

---

## 2. 核心交互逻辑与参数传递

在原型设计中，以下三个交互场景是数据流转的关键：

### A. 择优筛选：从画像列表到多维对比

- **交互路径**：在`可调节资源画像` 勾选资源 $\rightarrow$ 点击“对比” $\rightarrow$ 进入`资源对比视图`。
    
- **参数传递逻辑**：
    
    - **传递项**：`Selected_Resource_IDs`（被选中资源唯一标识数组）。
        
    - **业务表现**：对比视图接收 ID 数组后，将画像页面中的雷达图数据（调节潜力、响应速度等）进行横向拉表显示，并计算均值或极值。
        

### B. 决策闭环：从预测缺口到资源调度

- **交互路径**：`实时负荷预测概览` 发现缺口 $\rightarrow$ 点击“去调节” $\rightarrow$ 跳转`可调节资源画像`。
    
- **参数传递逻辑**：
    
    - **传递项**：`Load_Gap_Value`（待调节负荷值）及 `Timestamp`（预测高峰时刻）。
        
    - **业务表现**：画像页面接收参数后，会自动在“推荐资源”列表中置顶显示那些“调节潜力”指标能覆盖该缺口的设备，并计算所需的聚合数量。
        

### C. 算法优化：从协同面板到细节微调

- **交互路径**：`多智能体协同面板` 监控异常 $\rightarrow$ 点击“查看详情” $\rightarrow$ 进入`智能体详细配置`。
    
- **参数传递逻辑**：
    
    - **传递项**：`Agent_Type`（智能体类别，如空调/基站）及其 `Current_Accuracy`（当前准确率）。
        
    - **业务表现**：详细配置页加载特定的“学习率”和“置信度阈值”滑动条。
        

---

## 3. 页面参数流转表

|**触发页面**|**目标页面**|**传递的核心参数**|**B 页面如何利用这些数据**|
|---|---|---|---|
|**可调节资源画像**|**资源详情弹窗**|`Device_ID`|获取该设备的 24 小时历史负荷曲线。|
|**实时负荷预测概览**|**多因子动态修正配置**|`Deviation_Rate` (偏差率)|提醒用户调整“影响权重”滑动条以修正特定因子（如气象）的敏感度。|
|**实时负荷预测概览**|**区域负荷地图视图**|`Timeline_Index` (当前时间索引)|地图同步渲染该时刻全省的负荷热力密度。|
|**多智能体协同面板**|**智能体详细配置**|`Active_Status` (启用状态)|决定配置页是否允许修改“学习率”等核心训练参数。|

## 💡 给设计整理的建议

为了让 Stitch 里的交互逻辑更具说服力，你可以关注以下“逻辑奇点”：

1. **预测公式的透明化**：在`多因子动态修正配置`中，权重的调节可以通过 LaTeX 公式展示其对结果的影响：
    
    $$L_{corrected} = L_{base} \times (1 + \sum_{i=1}^{n} w_i \cdot f_i)$$
    
    其中 $w_i$ 是用户在页面调节的“影响权重”。
    
2. **空间与时间的联动**：确保`区域负荷地图视图`的时间轴 与`实时负荷预测概览` 的时间轴刻度（如 15min/粒度）保持严格一致。
    
3. **画像维度的继承**：`资源对比视图`中的六维指标名（调节潜力、响应速度等）必须与`可调节资源画像`中的雷达图顶点完全对齐。

5. **安全闭环监控**：通过 **[告警规则配置]** 与 **[告警历史记录]**，为能力缺口设定自动预警机制。

#### 2. 地域层级下钻 (Map $\rightarrow$ Detail)

- **路径**：在`可调能力区域热力图` 点击地图上的“杭州市”区块。

- **目标页展示**：`可调能力详情` 接收 ID 后，页面标题更新为“杭州市”，底部的“相关资源组成”列表自动加载属于杭州区域的子资源及其容量占比。
    

#### 3. 约束因子效能映射 (Config $\rightarrow$ Visualization)

- **路径**：在`约束条件配置面板` 调整“影响权重”或具体参数后，点击“保存并查看影响”。
    
- **参数传递**：传递全量 `Constraint_Set` (包含碳排放、调节速率、舒适度等各项的权重与阈值)。
    
- **目标页展示**：`约束影响可视化` 页面利用这些参数计算出“能力降低值”（如 730 kW），并以此更新地图各区域的颜色深浅，直观展示约束条件最吃紧的地区。
    

#### 4. 阈值触发关联 (Dashboard $\rightarrow$ Alarm Config $\rightarrow$ History)

- **路径**：用户参考 `预测看板` 中的“总可调容量”设定告警规则。
    
- **参数传递**：`Alarm_Threshold` (如 1000 kW) 和 `Target_Scope` (告警对象：全局/杭州市)。
    
- **目标页展示**：当实际预测值低于此阈值时，`告警历史记录` 会生成一条记录，并将“触发表述”设定为“当前值 950kW < 阈值 1000kW”，同时携带该记录的 `Target_ID`。

### 5-12-“异构资源聚合”模块总结
```

2. **管理中枢**：**[异构资源聚合仪表盘]** 作为入口，监控网关、机组和策略的全局状态。

    - 通过 **[边缘策略管理]** 维护下发至网关的调度算法。
        
    - 通过 **[边缘策略配置]** 设定目标权重与安全约束。
        
    - 通过 **[边缘策略下发]** 完成从虚拟仿真到物理执行的最后闭环。

#### 1. 资源聚合闭环：从机组定义到动态优化

#### 2. 策略部署闭环：从逻辑定义到安全下发

- **交互路径**：`边缘策略管理` $\rightarrow$ 点击“配置” $\rightarrow$ `边缘策略配置` $\rightarrow$ 点击“版本历史” $\rightarrow$ `边缘策略版本历史` $\rightarrow$ 返回管理页点击“下发” $\rightarrow$ `边缘策略下发`。
