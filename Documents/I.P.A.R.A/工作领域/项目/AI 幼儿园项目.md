## 项目速查

系统汇集饮水、手环和用餐记录，供老师、园长及家长查看。唐山一幼的餐盘拍照设备放在教室，小朋友在教室用餐。

- 2026-11-17 的版本台账记录服务端 V1.2、现场设备 V1.1。空盘照片已在服务端排除，设备上的重拍提示还需更新。使用前查看[飞书版本台账](https://jizhishida.feishu.cn/docx/SAfbdDp06oMRBJxh7thcvtj4nJg)。
- 现场核对时记录前方摄像头镜头中心到地面、朝下摄像头镜头中心到餐盘桌面的高度，单位用厘米。
- 常用入口见[系统后台](https://kg.jizhishida.com/admin/)和[项目介绍网站](https://ai.jizhishida.com/)。
- 本机项目目录为 `~/code/smart_vision/aiKindergartenSystem/`。资料入口见 `docs/资料目录.md`，现场进展见 `docs/当前状态与待办.md`，应用代码位于 `ai-kindergarden/`。

### 2026-11-18 教室餐盘拍照排查

- 状态：草稿
- 现场反馈：这两天后台未看到午餐照片，设备在教室。需核实是否有拍照、两路摄像头的安装高度，以及后台是否收到并保存记录。
- 待斟酌：先拿到现场取景和一次试拍的时间，再判断是操作流程、设备取景、版本差异还是上传链路的问题。

```text
请帮我排查唐山一幼教室的午餐拍照记录。现象是后台近两天未看到午餐照片。餐盘拍照设备在教室，小朋友在教室用餐。

第一轮做只读检查。先核对本地源码、服务端和现场设备各自的版本，再沿着「拍照 → 选片 → 上传 → 识图 → 后台展示」梳理流程。按已有证据列出确认的现象、可能原因和还需现场补充的资料。现场可补充两路镜头高度、餐盘取景照片以及一次试拍的时间。

给出可单独验证的最小改动建议。验证时覆盖完整餐盘正常记餐、空盘不计入用餐、放好餐盘后能再次拍摄。逐项注明适用版本和验证结果。
```

### 2026-11-18 后续开发计划提示词 v1.1

- 本版取舍：先核对发布源码并搭独立测试环境，改动在测试环境验收后按发布流程上线。再核对体温字段，再用手机工作台原型评审学生详情和缺采筛选。现有 AI 小结优先复用，园长汇报基于试点记录。
- 试跑产物在本机项目的 `docs/生活监测系统开发计划-2026-11-18.md`，原型位于 `output/开发规划-2026-11-18/原型/`。

```text
你是 AI 幼儿园生活监测项目的产品和技术搭档。请基于当前项目证据，执行一次后续开发规划，产出可评审的计划、分期任务、验收标准和中文移动端原型图。请实际查阅源码和资料后给结论，首轮交付止于规划与原型，评审后先搭建独立测试环境，再进入应用开发。禁止在正式环境直接修改代码、配置或数据库。

背景
- 项目已有饮水、手环、用餐照片三条采集链路，以及老师工作台、园长端和家长端。唐山一幼在教室用餐，餐盘设备也在教室。老师主要用手机，部分老师需要大字、高对比度和容易点到的控件。
- 老师反馈教师端看不到家长端已有的手环体温。现场有过午餐照片缺失和朝下摄像头未对准的情况。请逐项区分现场观察、源码结论、台账记载和仍待核验的线上行为。
- 园长需要向上级汇报「AI 赋能幼儿园」成果。设计可核验的试点成果汇报，清楚写出时间范围、覆盖班级、数据来源、样本数、缺失情况和审核人，用真实证据支撑数字。

请完成以下工作
1. 读取项目 README、交接、状态待办、发布台账和当前可取得的 Git 引用。列出现有页面、角色权限、AI 入口及数据流。为关键结论注明文件行号或来源日期。发现代码与发布不一致时分别记录，不以旧源码推断线上。
   把测试环境作为 P0 前置任务。单独部署 Flask、SQLite、账号和设备模拟入口，使用合成数据及测试配置，隔离正式数据库、设备凭据、通知渠道、模型密钥。列清可重复搭建方式、验收用例和发布门槛。应用改动先从测试分支部署到测试环境，验收通过且演练回退后，再用经审查的提交与发布标签上线。正式环境按发布流程变更。
2. 针对手环、水杯和餐盘建立字段清单，逐项核对设备提供、服务接收、入库、老师页面、家长页面。给出应该加到班级列表、学生详情、园长聚合或仅内部诊断的字段。重点核对体温、最后采集时间、步数、血氧、饮水量和电量；辨别体温与水温、真零与缺失、有效餐次与已上传照片。
3. 设计「日常工作台 / 园务管理」两个入口，优先沿用同一登录和数据服务。老师登录后可直接看到本班列表，单点进入学生详情集中查看今日和历史饮水、体温、心率、用餐、关注记录及 AI 小结。压缩顶部导航；从默认落地页到常用功能最多点三次，列路径并计数。标明权限与保留的旧路径。
4. 为列表设计「全部 / 已有数据 / 今日缺数据」筛选，解释部分缺失、尚无数据、未绑定、非在园、未到采集时段、旧数据和技术故障的区分。提醒和采集状态分别显示，避免把有数据写成健康正常。
5. 调研共享报告和掌心宝贝、illumine AI、Nuvilab × CJ Freshway。用官方资料核对可借鉴的流程和公开落地证据。优先参考移动角色工作台、AI 起草后由人审核、孩子容易理解的餐盘定位与重拍反馈。说明哪些功能适合现在做、哪些需等数据质量和现场流程验证。
6. 先制作符合幼儿园气质的中文手机原型，至少覆盖班级列表、学生详情、园长成果、园务管理。以暖色和清晰文字为主，交互目标至少 48 CSS px，正文建议 18 CSS px，次要文字至少 16 CSS px，支持放大和窄屏。给出页面状态、筛选和关键操作路径，原型使用虚构数据。
7. 交付 P0/P1/P2 任务计划。注明依赖、预计工期、涉及的模块、验收方式和回退策略。首先解决影响每天使用的数据展示和动线，再做由真实记录产生的班级 AI 日报、园长周报及脱敏导出。无基线的成效项写待测，数据不足时显示覆盖与缺项，AI 内容须能溯源并经人工审核。
```
