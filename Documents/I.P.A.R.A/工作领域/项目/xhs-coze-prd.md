> 用 **Coze（扣子）工作流**重新搭建。目的：让软件公司小红书号保持活跃度，稳定产出"主号风格"图文。

---

## 1. 背景与目标

- **账号**：小红书号 `49755699915`，一家**软件 / 定制开发公司**的官方号。
- **目标**：保持账号活跃度，低摩擦、稳定地产出符合主号调性的图文笔记（文案 + 配图）。
- **方式**：飞书（或 Coze 调试面板）发一句话 → Coze 工作流出"文案 + 3 张配图" → 回对话框 → **人工**复制到小红书发布。
- **为什么不自动发布**：本期不做（小红书对发布动作有强反自动化，且账号是公司主号、封号代价高）。自动发布作为未来可选项（第 10 节）。

## 2. 范围与非目标

**做**：对话触发（带主题 / 裸触发自动选题）→ 按主号风格生成一篇图文文案 → 生成 3 张 3:4 配图 → 文案+图片一起回对话框。

**不做（本期）**：自动发布到小红书；自动定时（人工触发即可）；多账号。

## 3. 输入 / 输出

**输入**（两种）：
- 指定主题：`写一篇小红书，主题：vibe coding`
- 裸触发：`来一篇小红书` → 自动从主题池挑一个新角度。

**输出**（一条回复 = 文本 + 图）：
```
🔥 <标题，≤20 字>
📅 <日期>
🖼️ 配图（3 张）：图1… 图2… 图3…
📄 完整文案（约 750 字）：<6 段正文>
+ 3 张图片（3:4）
```

## 4. 内容风格规范（核心 —— 直接作为 Coze LLM 节点的 System Prompt）

### 4.1 主题范围（固定，跑偏要拉回）
账号是软件 / 定制开发公司。**每篇主题和新闻钩子必须落在**：
软件开发、互联网行业、AI Agent、vibe coding、定制开发、低代码、SaaS、独立开发 / 独立开发者、MCP、大模型应用 / 落地、数字化转型、效率工具、技术出海。
- 禁止纯传统行业话题（餐饮 / 美容 / 服装批发等）——除非视角是"他们需要软件 / AI 来升级"。
- 客户故事里的"小老板"可以是：独立开发者、创业团队 CTO、SaaS 公司、互联网中小企业、或需要软件定制的传统企业老板——**痛点必须和软件 / AI / 数字化相关**。

### 4.2 人设
做定制软件开发的创业者。务实、接地气。信条："最好的技术，是能沉下去的技术"——不一定要多高算力、多复杂模型，而是深刻理解某个真实痛点，把方案织进日常流程。

### 4.3 每篇结构（正文约 750 字，6 段，缺一不可）
1. **新闻钩子**：一条最近的技术 / 科技新闻开场（1-2 句，可合理拟一条贴切的）——必须落在主题范围。
2. **客户故事**：一个具体的人——姓 + 职务（王总、陈厂长、独立开发者小张、CTO 林总、出海创业者老周），点明处境，用**场景化细节**写他和软件 / AI 相关的真实痛点。
3. **诉求**：他找"我们"做定制开发（或用某个 AI / 软件方案），诉求很简单、很具体。
4. **方案**：我们 / 他做了什么——精简、不花哨、对口，调子是"方案说出来一点都不性感"那种。
5. **效果**：上线 / 用上后的变化，带感受或数字（如响应率 50%→85%、晚上能陪孩子了）。
6. **反思**：结尾一段对"技术 / 做软件"的感悟——接地气、反对唯新唯大、强调沉下去 / 用得上 / 用得好。

### 4.4 语气
像创业者在聊天，不端着；定制开发的布道者视角。可用"说实话""我一直觉得"这种口语。

### 4.5 输出格式（严格，前后不加解释、不加代码块）
```
🔥 <标题，≤20 字，要有反差或感悟感>
📅 <今天日期，YYYY年MM月DD日>
🖼️ 配图（3张）：
  图1: <封面标题卡，一句话说明画什么>
  图2: <金句或内容卡>
  图3: <数据或对比卡>
📄 完整文案（约750字）：
<正文，严格按 6 段结构>
```

### 4.6 多样性
每次主动换新角度 / 子话题，在主题池轮换，不要连续两篇同一钩子或同一行业。

## 5. 配图规范

- **3 张，3:4 竖图**（小红书图文比例）。
- 图1 = 封面：突出标题氛围，场景化插画，干净简洁。
- 图2 = 金句卡：文案里最有感觉那句话的视觉化。
- 图3 = 数据 / 对比卡：上线前后对比或关键数字的视觉化。
- 每张图的画面 prompt 由"写文案"节点同时产出（在 4.5 格式的"配图"部分），供图像生成节点使用。

## 6. Coze 工作流设计（建议）

```
[开始/输入] → [选题] → [写文案 LLM] → [拆解 Code] → [出图×3 并行] → [输出]
```

| 节点 | 类型 | 说明 |
|---|---|---|
| ① 输入 | 开始节点 | 入参 `topic: string`（可选）。来自飞书机器人 / Coze 调试面板消息。 |
| ② 选题 | LLM 或 Code | `topic` 空 → 从主题池（4.1）挑新角度；非空则透传。出参 `chosen_topic`。 |
| ③ 写文案 | LLM | **System Prompt = 第 4 节全部**；User = `主题：{{chosen_topic}}`。按 4.5 格式输出整篇。模型建议 Doubao / 豆包（或 GPT 类），需中文长文能力。 |
| ④ 拆解 | Code 节点 | 把 ③ 输出拆成 `title`、`date`、`body`、`img_prompt_1/2/3`。 |
| ⑤ 出图 a/b/c | 图像生成（3 并行分支） | 各取一个 `img_prompt`，调 Coze **图像生成插件 / 节点**（豆包图像 / 即梦 / Universal Image），比例 **3:4**，产出图片 URL。 |
| ⑥ 输出 | 结束节点 | 文本（title+body+标签）+ 3 张图片 URL，作为机器人回复。 |

**关键点**：
- ③ 的 System Prompt 是成败核心——直接粘贴第 4 节。
- ⑤ 用 Coze 内置图像生成，无需自己管 API key。
- 工作流包成 **Coze 智能体/Bot**，**发布到飞书**，对话框触发。

## 7. 触发词 / 示例

- **A 只出文案**：`来一篇小红书` / `写一篇小红书，主题：vibe coding`
- **B 文案 + 3 图**：`写一篇小红书，主题：AI Agent 给独立开发者提效。写完把 3 张 3:4 配图也生成出来，一起发我`

> Coze 里做成一个 Bot：收到消息 → 跑工作流 → 回复。A/B 可以是同一个工作流（默认就出图），或意图判断分流。

## 8. 风格基准（校准用）

主号真实样稿共性（来自 3 篇历史笔记：货运 AI 管家 / 异算方舟国产 AI 硬件 / 成都 AI 创业系统）：
> 🔥 标题 + 科技/财经新闻钩子 → 具体小老板客户故事（场景化痛点）→ 简单定制诉求 → 精简方案 → 带数字效果 → 反对唯新唯大的反思。~750 字、3 图。人设：务实、接地气的定制开发创业者。

校准一句话：写出来的稿子，要让人感觉是"一个做定制开发的创业者在聊天"，不是"AI 在写营销软文"。

## 9. 验收标准

1. 飞书发 `来一篇小红书` → 30~90 秒内回完整图文 + 3 张 3:4 图。
2. 文案符合 6 段结构、主题在主题池内、字数 ~750、标题 ≤20 字带 🔥。
3. 连续 5 次裸触发，主题 / 行业不重复（多样性）。
4. 配图 3:4、与文案对应（封面 / 金句 / 对比）。
5. 指定主题时按指定写；主题跑偏（如纯餐饮）时自动拉回到软件 / AI 视角。

## 10. 未来扩展（可选，不在本期）

- **自动发布到小红书**：`xpzouying/xiaohongshu-mcp`（rod 干净浏览器，绕过反自动化）做发布插件，工作流末尾调 `POST /api/v1/publish`。先测试号验证。
- **选题不重复记忆**：工作流读写"已用主题"列表（数据库 / 文件节点）。
- **定时产出**：Coze 定时触发 + 飞书群推草稿。
- **多账号 / 多人设**：变量化人设和主题池。

## 11. 备注 / 避坑

- 之前在 Mac 上的 Hermes/OpenClaw 也实现过同样能力（`xhs-writer` skill + MiniMax 出图），验证过风格和出图都通。Coze 版是把同一套**风格规范**搬到 Coze 工作流，**出图改用 Coze 内置图像生成**（不用自己管 key），更省心。
- 小红书**发布按钮有反自动化**（CDP/Playwright 附着的浏览器看不到发布按钮），所以"自动发布"必须用 rod 干净浏览器或官方商务接口，本期不做。
