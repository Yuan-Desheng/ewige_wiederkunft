# 优化要求

请重点针对以下7个方面对原开发计划进行修订和补充：

## 1. 消息通知/待办提醒模块（原计划缺失）
- 问题：文档反复出现“反馈综合岗”、“通知项目管理人员”，但原计划没有设计消息通知机制。在真实OA中，退回后无人收到待办提醒会导致流程卡死。
- 要求：
  - 设计 message 消息通知表（id, receiver_id, biz_type, title, content, is_read, created_at）
  - 在 StateMachineService 的 onEnter 动作中，强制绑定发送待办消息（如“您有一条新的评审任务”、“您的申请已被退回”）
  - 前端工作台显示红点/未读计数
  - 在功能模块划分中新增“消息通知”模块

## 2. 派单模型优化（重排逻辑模糊）
- 问题：原计划的 PLANNED → AUDITING 是原子操作。如果派单后审核员临时拒绝，或项目被毙需部分撤销（换掉组内1人），当前状态机没有对应的“局部重排”状态。
- 要求：
  - 引入 AUDIT_ASSIGNING（派单中）状态，允许综合岗反复调整 audit_assignment 表的 assign_status（推荐/确认/撤销），直到点击“锁定派单”才流转到 AUDITING
  - 增加“换人”动作：AUDITING 状态下，综合岗可触发 REASSIGN 动作（不改变项目主状态，只改子任务分配），操作日志记录变更
  - 更新状态转换表，体现 AUDIT_ASSIGNING 和 REASSIGN 动作

## 3. Excel 导出模板配置化
- 问题：需求原文提到“表单另附”，但原计划只说了技术实现（FastExcel），没有说明表头模板是否可配。
- 要求：
  - 增加 export_template 表（id, template_name, columns_json, file_name_pattern），综合岗可在后台配置导出的列头与顺序
  - 导出时根据 project.domain_code 匹配对应模板
  - 在功能模块中增加“导出模板管理”

## 4. 工作日/节假日缓存表
- 问题：原计划派单用 holiday-cn，但人日数计算在申请评审时就需要。如果评审策划人定“5人日”，系统需要自动排除周末和节假日计算截止日。
- 要求：
  - 增加 work_calendar 表（date DATE, is_holiday BOOLEAN, is_workday BOOLEAN），每年年初初始化，支持管理员手动调休
  - 在 review_plan 里增加 plan_deadline（系统根据人日数+日历自动算出）
  - 说明节假日数据初始化方案

## 5. 接口契约提前锁定
- 问题：原计划中 M5（前端框架）与 M1/M2 并行，但后端API还没写，前端只能做静态页面，效率低。
- 要求：
  - M0阶段增加子任务：产出《API接口文档（初稿）》（用 knife4j/Swagger 或 Apifox 定义好所有接口的URL/入参/出参）
