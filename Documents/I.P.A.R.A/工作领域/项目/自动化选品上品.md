## 一、现状工作流拆解（基于真实操作 + 官方帮助站）

> 来源：源文件 [[自动化选品上品（原始需求）（目前可行方案）]] 的操作截图 + 布丁猫官方帮助站 `help.bdmozon.com` + 八爪鱼私享应用。

### 1.1 完整链路

```text
① 前台准备(布丁猫插件): OZON前台切【俄语/人民币/收货地址莫斯科】
        │
② 选品(布丁猫插件): 浏览OZON, 插件显示销量框, 找爆款竞品
        │
③ 采集+上品(布丁猫「快速上传/采集上货」= 接口上传, 走OZON Seller API):
        复制竞品SKU → 编辑属性(去品牌/改图/货号/变体) → 打乱图 → ×2.3调价
        → ×0.5最低价 → 打水印(防踢跟卖) → 5分钟后加库存10 → 选店铺 → 开始导入
        │  （批量≤200, 推荐每次≤5; 必须先切俄语否则报品名错误）
        │
④ 导出SKU表: 复制sku → 新建工作表移到最前 → 粘贴 → 保存
        │
⑤ 货源验证(八爪鱼「陆空联运/陆运」私享应用):
        读SKU表 → 逐个用商品图去【1688拍立淘图搜】(air.1688.com/.../pc-image-search)
        → 有同款货源? ──有──→ 上架  ；  ──无──→ 不上架
```

## 二、需求分析

### 2.1 业务模型

OZON（俄罗斯跨境）多店精铺 + 国内供货：**OZON找爆款竞品 → 采集SKU → 1688反向找同款货源+比价 → 翻译/改价/打水印 → 批量上品到自己OZON店 → 库存/订单管理**。

### 2.2 四大痛点（自研要解决的目标）

1. **成本高 / 被卡免费额** —— 布丁猫、八爪鱼都是付费 SaaS，限量、数据在别人手里 → 要完全自托管。
2. **1688 找同款 + 比价不够智能** —— 图搜验证 + 利润测算要更自动、更准。
3. **选品数据不准 / 不全** —— OZON 无官方竞品销量，要自建可信的"卖得好不好"数据。
4. **上品效率 / 批量能力差** —— 采集→翻译→改价→多店上传要真正批量、稳定。

### 2.3 关键事实（可行性）

- ✅ **OZON 官方 Seller API 可用**（`Client-Id`+`Api-Key`，你已生成密钥）→ 上品/改价/库存/订单全走官方 API。布丁猫「接口上传」证明此路可行。
- ⚠️ **OZON 有反爬**（DDoS-Guard）→ 买家端采集/选品数据用**浏览器插件复用登录态**最稳（布丁猫插件同理）。
- ⚠️ **1688 官方图搜 API（拍立淘）需企业认证**（营业执照）→ 见风险三路径。
- ⚠️ 俄语字符 / 品名规则严格 → 上品前必须处理翻译与字符。

## 三、方案设计（架构 A：混合三件套）

### 3.1 架构总览

```text
┌─────────────────────────┐        ┌──────────────────────────────────────┐
│  Chrome 插件 (MV3)       │        │   Web 后台 (阿里云 ECS)                │
│  —— 采集/选品端 + 工具箱   │        │   —— 大脑 + 上品端                     │
│                         │        │                                        │
│ · 复用OZON登录态:         │──HTTP─▶│  FastAPI 后端                          │
│   显示销量/采集竞品/SKU    │  上报   │   ├ SKU 库 (PostgreSQL)                │
│ · 一键商品图→1688图搜      │        │   ├ 选品分析(销量估算/趋势/竞争度)       │
│ · 工具箱:切俄语/人民币/     │◀─指令──│   ├ 1688图搜货源验证 + 比价 + 利润测算   │
│   莫斯科/汇率/运费计算      │        │   ├ 翻译(阿里云/DeepSeek) + AI文案      │
└─────────────────────────┘        │   ├ 上品引擎(打乱图/调价/水印/货号/变体) │
                                    │   ├ 水印引擎(模板/每店不同/防跟卖)       │
        ┌──────────────┐           │   ├ 商品/库存/订单管理 + 利润看板        │
        │ 1688/拼多多   │◀─图搜/比价─│   └ 定时任务(回采榜单/评论→估算销量)     │
        │ 找货源(API/爬) │           └───────────┬───────────────┬──────────┘
        └──────────────┘                        │ OZON Seller API │
                                    ┌────────────▼─────────────────▼─────────┐
                                    │  OZON 卖家(多店): 建品/改价/库存/订单    │
                                    └──────────────────────────────────────────┘
```

**为什么 A**：① 采集/选品复用登录态→**防封**；② 上品走官方 API→**最稳批量**（布丁猫「接口上传」已验证）；③ 后端自托管→**成本/数据自主**。

### 3.2 子系统拆解

| # | 子系统 | 替换 | 职责 | 关键技术 | 风险 |
|---|--------|------|------|----------|------|
| **S1** | **上品引擎** | 布丁猫快速上传 | 批量建品，含打乱图/调价×倍率/最低价/水印/货号生成/变体/延迟库存/多店浮动 | OZON Seller API + 任务队列 + 图片处理 | 低（官方API最确定） |
| **S2** | **采集/选品端(插件)** | 八爪鱼+布丁猫插件 | 复用登录态采集OZON商品/图片/SKU/销量框；1688图搜触发 | Chrome MV3 + OZON内部JSON接口 + cookie复用 | 中（反爬/接口变动） |
| **S3** | **1688货源验证+比价** | 八爪鱼陆空联运+布丁猫 | 商品图→1688拍立淘图搜→有同款才上架(gate)；到手成本/毛利测算 | 拍立淘图搜 + 利润公式 + 汇率/头程/佣金 | 中（1688认证/成本） |
| **S4** | **选品分析** | 布丁猫选品分析 | 榜单/评论回采→销量估算/趋势/竞争度打分 | 定时任务 + 时序回采 + 评论增量估销 | 高（估算准确性） |
| **S5** | **水印/防跟卖** | 布丁猫水印管理 | 水印模板、每店不同水印、公司logo合成 | 服务端图片合成(Pillow) | 低 |
| **S6** | **翻译/AI文案** | 布丁猫AI+阿里云翻译 | 中↔俄翻译、标题/属性AI生成、俄语字符纠错 | 阿里云翻译/DeepSeek | 低 |
| **S7** | **管理面板+工具箱** | 布丁猫后台+插件 | 多店/商品/库存/订单/利润看板；切语言货币、汇率运费计算 | Vue/React + 汇率API | 低 |

### 3.3 核心接口（已核实）

**OZON Seller API**（Header `Client-Id`+`Api-Key`；文档 `docs.ozon.ru/global/en/api/`）

| 用途 | 接口 |
|------|------|
| 批量建品/更新（一次 ~100 件） | `POST /v2/product/import`（新版 `/v3/product/import`） |
| 建品/审核状态（审核约3天） | `POST /v1/product/import/info` |
| 批量改价 | `POST /v1/product/import/prices` |
| 批量改库存 | `POST /v1/product/import/stocks` |
| 类目树 / 类目属性 | `POST /v1/description-category/tree`、`/v1/description-category/attribute` |
| 订单（FBS） | `POST /v2/posting/fbs/list` |

建品关键字段：`offer_id`、`name`、`description_category_id`、`price`/`old_price`、`vat`、`images`、`attributes`、`dimensions`、`weight`。

**1688 图搜（拍立淘）**：端点 `https://api.1688.com/router/rest`；参数 `search_type`(1=精确同款/2=相似)、`cat_id`、`min_order`、`page/page_size`(≤50)；返回 标题/价格区间/起订量/供应商/相似度分。前台图搜页 `air.1688.com/kapp/1688-search/pc-image-search`。

### 3.4 开发路线图（先做技术最确定、价值最大的）

```text
P0  地基 + S1 上品引擎         跑通单店"接口上传"(建品/调价/最低价/货号/延迟库存)，替换布丁猫上货  ★最确定
P1  S5 水印 + S6 翻译/AI       打水印(防跟卖) + 中俄翻译/字符纠错，让 P0 的品能合规上架
P2  S2 采集/选品端(插件)        复用登录态采集 OZON 商品/图片/SKU/销量框 入库
P3  S3 1688图搜货源验证+比价     图搜找同款做"有货源才上架"gate + 自动算毛利
P4  S4 选品数据               定时回采榜单/评论→估算销量趋势（解决"数据不准"）  ★最难
P5  S7 管理面板+工具箱          多店/订单/库存/利润看板 + 切语言货币/汇率运费
```

原则：**P0/P1 先把"能批量、合规地上品"这条价值最大、风险最低的主干打通**（这一步就替换掉布丁猫核心 + 八爪鱼），最难的选品数据估算(P4)往后放、边跑边积累回采数据。

### 3.5 关键技术风险与对策

1. **OZON 反爬/封号** → 采集/选品**只用浏览器插件复用真实登录态**，不做服务端无头爬；控制频率、随机延时；上品走官方 API（合规）。
2. **选品数据无官方来源** → 自建：定时回采类目榜单 + 商品**评论数增量**(Δ评论≈销量代理) + 排名变化 → 时序库估算趋势与竞争度。P4 慢慢调准。
3. **1688 官方图搜需企业认证** → 三路径：**A.官方开放平台**(需营业执照，你有主体可申请，最合规) / **B.第三方聚合API**(万邦/onebound，按量付费，免认证上手快) / **C.自建拍立淘爬取**(零API成本但维护重易风控，不推荐)。建议**先B跑通→再A转正降本**。
4. **俄语品名/字符错误** → 上品前统一走翻译 + 字符校验清洗（布丁猫踩过这个坑）。
5. **防踢跟卖** → S5 水印 + S1 打乱图/多店浮动，复刻布丁猫的差异化策略。
6. **多店密钥安全** → 各店 `Client-Id`/`Api-Key` 存服务器 `.env`(mode 600)，**绝不进 git**；后台加密存库。

### 3.6 技术栈与部署

| 层 | 选型 | 理由 |
|----|------|------|
| 后端 | **Python + FastAPI** | 契合 TDD/pytest；生态适合爬取/图片/数据处理 |
| 数据库 | **PostgreSQL** | SKU 库 + 时序回采数据 |
| 任务队列/定时 | Celery / APScheduler | 上品异步、榜单回采定时 |
| 图片处理 | Pillow | 打乱图、水印合成 |
| 前端后台 | **Vue 或 React**（待定） | 多店/商品/选品/利润面板 |
| 采集/选品端 | **Chrome 插件 (MV3)** | 复用登录态、低封号风险 |
| 翻译/AI | 阿里云翻译 / DeepSeek | 中↔俄，成本低 |
| 部署 | **阿里云 ECS**（已有）+ codeup 仓库 `autoPickShelf` | 复用现有基础设施 |

### 3.7 成本对比

- **现状**：布丁猫月费 + 八爪鱼月费 + 被限量，数据受制于人。
- **自研**：一次性开发 + 阿里云 ECS（已有）+ 1688/翻译 API 按量。**边际成本趋近零、数据全自主、功能随需求迭代**。
