## 需求分析（2026-07-14 梳理）

### 1. 业务模型

在 **OZON（俄罗斯跨境电商）** 上运营多个店铺（ROSIN Boutique、Russia Flagship / Premium / Victory Store 等），做「精铺 + 国内供货」：

```text
OZON 找爆款竞品 → 采集 SKU（数据+图片） → 拿商品图去 1688 反向找同款货源 + 比价算利润
        → 决策（值不值得做） → 翻译 + 改价 → 批量上品到自己 OZON 店 → 库存/订单管理
```

### 2. 现状工具链与痛点

| 工具 | 类型 | 干什么 | 痛点 |
|------|------|--------|------|
| **八爪鱼 Octoparse** | RPA 爬虫 | 采集竞品/货源商品数据、图片 | 付费、被卡免费额、通用工具不贴场景 |
| **布丁猫 bdmozon** | OZON 选品助手插件 + 店铺管理 SaaS | 插件：浏览/切语言货币/汇率运费/AI；后台：店铺、快速上货、采集上货、商品/库存/订单管理、下架重上 | 月费、限量、数据在别人手里、选品数据不准、上品批量能力/效率差 |

**四大痛点（全部命中，即本项目要解决的目标）：**
1. **成本高 / 被卡免费额** —— 想彻底自托管，数据、额度自己掌控。
2. **1688 找同款 + 比价不够智能** —— 目前靠手工识图 + 手工算利润，慢。
3. **选品数据不准 / 不全** —— 说不清 OZON 上哪个品真的卖得好（销量、趋势、竞争度）。
4. **上品效率 / 批量能力差** —— 采集→翻译→改价→多店上传，慢、卡、一次传不了多少。

### 3. 目标

自研一套**完全自托管、端到端的 OZON 选品上品平台**，一次性替换布丁猫 + 八爪鱼整条链路。给自己 / 小团队用。

### 4. 关键事实（决定技术可行性）

- ✅ **OZON 官方 Seller API 可用**：`Client-Id` + `Api-Key`（你已在卖家后台生成「布丁猫」「物流系统」两个密钥）→ 上品 / 改价 / 库存 / 订单**全部可走官方 API**，不必靠浏览器 RPA。
- ⚠️ **OZON 有反爬**（DDoS-Guard / Qrator）：买家端商品数据不宜服务端无头爬——布丁猫的「复制 OZON 登录凭证」正是复用真实登录态。**采集端用浏览器插件（复用你登录态）封号风险最低。**
- ⚠️ **1688 官方图搜 API（拍立淘）需企业认证**（营业执照），个人开发者不可用——见方案「五、风险」的三条备选路径。

## 方案设计（架构 A：混合三件套）

> 定位：这是**决策蓝图**（需求 + 架构 + 子系统拆解 + 路线图），不是实现代码。逐块技术方案在各子系统立项时再展开为复现篇。

### 一、架构总览

三件套：**浏览器插件（采集端） + Web 后台（大脑 + 上品端） + 官方 API（执行端）**。

```text
┌─────────────────────────┐        ┌──────────────────────────────────────┐
│  Chrome 插件 (MV3)       │        │   Web 后台 (阿里云 ECS)                │
│  —— 采集端 / 工具箱       │        │   —— 大脑 + 上品端                     │
│                         │        │                                        │
│ · 复用 OZON 登录态采集    │──HTTP─▶│  FastAPI 后端                          │
│   商品/榜单/图片/SKU      │  上报   │   ├ SKU 库 (PostgreSQL)                │
│ · 一键把商品图丢 1688 图搜 │        │   ├ 选品分析 (销量估算/趋势/竞争度)      │
│ · 工具箱: 切语言货币/      │◀─指令──│   ├ 1688 比价撮合 + 利润测算            │
│   汇率/运费计算           │        │   ├ 翻译 (DeepSeek/Yandex)             │
└─────────────────────────┘        │   ├ 上品/改价/库存/订单 引擎            │
                                    │   └ 定时任务 (回采榜单/评论→估算销量)    │
        ┌──────────────┐           └───────────┬────────────┬──────────────┘
        │ 1688 找货源   │◀─── 图搜/比价 ────────┘            │
        │ (API/爬取)    │                                    │ OZON Seller API
        └──────────────┘                        ┌───────────▼──────────────┐
                                                 │  OZON 卖家 (多店)          │
                                                 │  建品/改价/库存/订单        │
                                                 └───────────────────────────┘
```

**为什么是 A**：① 采集复用登录态→**防封**；② 上品走官方 API→**最稳最快批量**；③ 后端自托管→**成本/数据自主**。

### 二、五大子系统拆解

每块可独立开发、独立上线见效。

| # | 子系统 | 替换 | 职责 | 关键技术 | 风险 |
|---|--------|------|------|----------|------|
| **S1** | **上品 / 店铺引擎** | 布丁猫后台 | 批量建品、改价、改库存、拉订单、下架重上 | OZON Seller API + 任务队列 | 低（官方 API，最确定） |
| **S2** | **采集端（插件）** | 八爪鱼 + 布丁猫插件 | 复用登录态采集 OZON 商品/榜单/图片→上报入库 | Chrome MV3、OZON 内部 JSON 接口、cookie 复用 | 中（反爬、接口变动） |
| **S3** | **1688 比价 / 找货** | 手工 + 布丁猫 | 商品图→1688 图搜同款→到手成本/毛利测算 | 拍立淘图搜、利润公式、汇率/头程/佣金 | 中（1688 认证/成本） |
| **S4** | **选品分析** | 布丁猫选品分析 | 榜单/评论回采→销量估算、趋势、竞争度打分 | 定时任务、时序回采、评论增量估销 | 高（估算准确性） |
| **S5** | **工具箱（插件内）** | 布丁猫插件 | 切语言/货币、汇率、运费计算器、快捷入口 | 纯前端 + 汇率 API | 低 |

### 三、核心接口（已核实）

**OZON Seller API**（认证：请求头 `Client-Id` + `Api-Key`；文档 `docs.ozon.ru/global/en/api/`）

| 用途 | 接口 |
|------|------|
| 批量建品 / 更新（一次最多 ~100 件） | `POST /v2/product/import`（新版 `/v3/product/import`） |
| 查建品 / 审核状态（审核约 3 天） | `POST /v1/product/import/info` |
| 批量改价 | `POST /v1/product/import/prices` |
| 批量改库存 | `POST /v1/product/import/stocks` |
| 类目树 / 类目属性 | `POST /v1/description-category/tree`、`/v1/description-category/attribute` |
| 订单（FBS） | `POST /v2/posting/fbs/list` |

建品关键字段：`offer_id`（你的货号）、`name`、`description_category_id`、`price` / `old_price`、`vat`、`images`、`attributes`、`dimensions`、`weight`。

**1688 图搜（拍立淘）** —— 端点 `https://api.1688.com/router/rest`；关键参数 `search_type`（1=精确同款 / 2=相似）、`cat_id`、`min_order`、`page/page_size`（≤50）；返回 标题 / 价格区间 / 起订量 / 供应商 / 相似度分。

### 四、开发路线图（先做技术最确定、价值最大的）

```text
P0  地基 + S1 上品引擎        先跑通单店"批量上品/改价/改库存"，立刻替换布丁猫上货  ★ 技术最确定
P1  S2 采集端（插件）          复用登录态采集 OZON 商品/图片/SKU 入库
P2  S3 1688 图搜 + 比价 + 利润  拿 OZON 图去 1688 找同款，自动算到手成本/毛利
P3  S4 选品数据               定时回采榜单/评论→估算销量趋势（解决"数据不准"）  ★ 最难
P4  S5 工具箱 + 多店/订单/库存面板  补齐布丁猫后台其余功能
```

原则：**P0 先落地价值最大、风险最低的官方 API 上品**，把最难的「选品数据估算」(P3) 往后放，边跑边积累回采数据。

### 五、关键技术风险与对策

1. **OZON 反爬 / 封号** → 采集端**只用浏览器插件复用你真实登录态**，不做服务端无头爬；控制频率、随机延时；上品走官方 API（本就合规）。
2. **选品数据「卖得好不好」无官方来源** → 自建：定时回采类目榜单 + 商品**评论数增量**（Δ评论 ≈ 销量代理指标）+ 排名变化 → 时序库估算销量趋势与竞争度。这是 P3 要慢慢调准的核心。
3. **1688 官方图搜需企业认证** → 三条路径按成本/合规权衡：
   - **A. 官方开放平台**（`open.1688.com`，需营业执照企业认证）—— 最稳最合规，你有公司主体可申请。
   - **B. 第三方聚合 API**（万邦 / onebound 等，按量付费）—— 免认证、上手快，但有成本和稳定性依赖。
   - **C. 自建拍立淘爬取** —— 零 API 成本，但维护重、易被风控，**不推荐**做主力。
   - 建议：**先 B 验证链路跑通，再 A 转正降本**。
4. **多店密钥安全** → 各店 `Client-Id`/`Api-Key` 存服务器 `.env`（mode 600），**绝不进 git**；后台加密存库。

### 六、技术栈与部署

| 层 | 选型 | 理由 |
|----|------|------|
| 后端 | **Python + FastAPI** | 契合你的 TDD/pytest 偏好；生态适合爬取/数据处理 |
| 数据库 | **PostgreSQL** | SKU 库 + 时序回采数据 |
| 任务队列/定时 | Celery / APScheduler | 上品异步、榜单回采定时 |
| 前端后台 | **Vue 或 React**（待定） | 店铺/商品/选品面板 |
| 采集端 | **Chrome 插件 (MV3)** | 复用登录态、低封号风险 |
| 翻译 | DeepSeek / Yandex Translate | 中↔俄，成本低 |
| 部署 | **阿里云 ECS**（你已有）+ 阿里云 codeup 仓库 | 复用现有基础设施，成本可控 |

### 七、成本对比（自研 vs 现状）

- **现状**：布丁猫月费 + 八爪鱼月费 + 被限量。数据、额度受制于人。
- **自研**：一次性开发投入 + 阿里云 ECS（已有）+ 1688/翻译 API 按量。**边际成本趋近于零，数据全自主，功能随需求迭代**。
