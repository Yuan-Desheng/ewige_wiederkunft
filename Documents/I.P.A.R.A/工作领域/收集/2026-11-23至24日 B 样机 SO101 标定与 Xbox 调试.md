## 2026-11-23至24日 B 样机 SO101 标定与 Xbox 调试

```meta-bind-embed
[[笔记抬头模块]]
```

> 本篇记录 2026-11-23 至 2026-11-24 的 B 样机单只 SO101 从臂实机调试。11 月 24 日，5 号手腕旋转恢复双向 Xbox 点动，保留原舵机。串口被旧实例占用时，可用本篇的一键启动脚本接管。

相关笔记见 [[B XLeRobot打印清单与配合验证]] 和 [[SO-ARM101 LeRobot 部署与调试记录]]。本次工时未记录。

### 11 月 23 日｜从臂标定、安卓手机和 Xbox

- 本机通过微雪舵机板的 USB 串口连接 B 从臂，舵机使用独立 12 V 供电。先后回读到 ID 1–6。首次标定中，个别关节出现跨过编码器零点的读数，异常记录留在项目目录。之后读了 A 从臂的限位作参考，B 的实际可用范围以各自采样和装配为准。
- 安卓手机通过 USB 调试将浏览器的 `http://localhost:18765` 转发到电脑。曾收到位姿并进入试操。一次串口超时使程序退出，手机显示 `ERR_EMPTY_RESPONSE`。断开 12 V 后重插微雪板到 1 号舵机的三针线，六只舵机重新回包，读到 **11.9–12.1 V**。另一次 AR 位姿跳变 **2.6 cm**，超过试操阈值 **2 cm**，控制程序退出。现场改用 Xbox，手机方案保留作后续调试。
- Xbox 蓝牙曾反复掉线，改用 USB 数据线，系统识别为 **Microsoft Xbox Series S|X Controller**，左摇杆和绿色 A 键实测通过。USB 也发生过短暂断开，手柄程序已加入重连。重新接上后需让摇杆回中并重新按 LB。
- 先用小行程逐轴确认 1–5 号，再把试用的窄窗口切换成已配置的范围。3 号肘部单独重录到 **870–3061**。6 号夹爪的自然停留读数曾低于旧下限 **2047**，手柄因此拦住动作。重录后范围为 **941–2380**。23 日收尾时夹爪只测到小位移。

### 11 月 24 日｜2 号带载跟随与 6 号开合

- **2 号大臂。** 右拨时目标 **1946**，实际停在 **1914**，远离软件上限 **3583**。只关闭 2 号扭矩后，原德胜手动试转该方向顺畅。前臂收近后右拨主观明显改善，现场确认可以继续操作。这次减载测试没有覆盖此前停住的同一角度，具体成因仍未完全定位。本次保留 2 号限位。
- **6 号夹爪。** 手柄程序提高了 6 号的点动步长，可以用 `--joint 6` 直接选中。24 日手柄日志记录夹爪从 **1027** 移到 **957**。已确认有实际位移，完整开合及抓取还需另测。

### 11 月 24 日｜5 号手腕旋转反向与恢复

1. 5 号在重录前可用。手动扫角跨过编码器零点后，曾把物理正中设为 **2047**，写入新偏移和窄限位。回读和就地保持通过后就恢复手柄，当时缺少双向点动验收。实机接到小幅减小位置的目标后，读数由约 **2039** 跳到 **4033**，随后出现报警。
2. 恢复旧标定、调整零位和重录范围都曾试过。脱开夹爪负载，用厂家格式的单条串口指令绕过 Xbox，目标从 **3050** 改为 **3022**，位置仍升到 **3126**，随即关断扭矩。重新装回后重录得到 **895–3065**，零位偏移为 **0**。单次测试仍出现反向，目标 **1970**，实际从 **1988** 升到 **2003**。
3. LeRobot 社区有人在同型号 **STS3215-C018 12 V、固件 3.10** 上报告了类似现象。其舵机写入较窄的硬件限位后，即使目标在范围内也会反向。另一个社区报告涉及跨零后残留整圈计数，本机普通位置和扩展位置都读到 **2675**，没有复现这项偏差。[窄限位反向报告 #3585](https://github.com/huggingface/lerobot/issues/3585) · [整圈偏差报告 #5324](https://github.com/huggingface/lerobot/issues/5324)
4. 临时把 5 号硬件限位放开到 **0–4095** 后，短测目标 **2650**，实测正确地从 **2674** 降到 **2658**。之后把这一配置正式应用，同时在 Xbox 和安卓控制代码中保留现场实测的 **895–3065** 软件边界。5 号仍启用低速和异常断扭矩保护，异常时只隔离 5 号，其他关节可继续用。
5. 正式改动后，Xbox 左拨和右拨都已实机验证。右拨回读由 **2004** 升到 **2034**，松开 LB 后停止，原德胜确认手腕在中间位置。保留原 5 号舵机。安卓代码通过环境检查，修复后的安卓实机遥操待测。

### Xbox 启动与串口占用处理

电脑接微雪板和 Xbox 手柄。进入项目目录运行以下命令。

```bash
cd ~/code/smart_vision/openRobotWholeMachine
./outputs/B-SO101手机遥操作/start_xbox.sh
```

看到 **Xbox ready** 后，默认选中 1 号。松开 LB 时按 A 切换关节。摇杆回中后按住 LB，再左右拨动。松开 LB 停止点动。

| 用途 | 启动参数 |
| --- | --- |
| 默认全范围操作 | 无需参数 |
| 直接选 5 号或 6 号 | `--joint 5` 或 `--joint 6` |
| 5 号已断扭矩时跳过它 | `--skip-joint 5` |
| 只释放控制程序占用 | `--stop` |

`OSError: Device or resource busy` 是另一进程已经打开串口的表现。本次实测是前一实例仍占着 `/dev/ttyACM0`。启动脚本识别本项目的 Xbox 和安卓控制进程，发送 SIGINT 并等待串口释放。未知占用者会显示 PID。已实测旧实例退出、新实例启动、只停止，以及未知占用者继续运行。**停止控制程序后，已开启扭矩的舵机仍保持位置。**

### 一键启动脚本全文

```bash
#!/usr/bin/env bash
set -euo pipefail

control_dir="$(cd -- "$(dirname -- "${BASH_SOURCE[0]}")" && pwd -P)"
python="$control_dir/.venv/bin/python"

if [[ ! -x "$python" ]]; then
    printf '找不到项目的 Python 环境：%s\n' "$python" >&2
    exit 1
fi

if [[ "${1:-}" == "--help" || "${1:-}" == "-h" ]]; then
    printf '%s\n' '默认释放项目控制程序的串口，再启动 Xbox 控制。--stop 只停止控制。'
    exec "$python" "$control_dir/xbox_usb_trial.py" --help
fi

exec "$python" -c "$(cat <<'PY'
import os
from pathlib import Path
import signal
import subprocess
import sys
import time


directory = Path(sys.argv[1])
args = sys.argv[2:]
controller = directory / "xbox_usb_trial.py"
known_programs = {controller, directory / "android_usb.py"}
serial = Path("/dev/serial/by-id/usb-1a86_USB_Single_Serial_5C94086642-if00")


def serial_owners(device):
    result = subprocess.run(["fuser", str(device)], capture_output=True, text=True)
    if result.returncode == 1 and not result.stderr.strip():
        return set()
    if result.returncode != 0:
        raise RuntimeError(f"无法检查串口占用：{result.stderr.strip()}")
    return {int(value) for value in result.stdout.split()}


def controller_path(pid):
    proc = Path("/proc") / str(pid)
    if proc.stat().st_uid != os.getuid():
        return None
    command = (proc / "cmdline").read_bytes().rstrip(b"\0").split(b"\0")
    if len(command) < 2 or not Path(os.fsdecode(command[0])).name.startswith("python"):
        return None
    arguments = command[1:]
    if arguments[0] == b"-u":
        arguments = arguments[1:]
    if not arguments or arguments[0].startswith(b"-"):
        return None
    return (proc / "cwd" / os.fsdecode(arguments[0])).resolve()


def stop_controller(pid):
    try:
        pidfd = os.pidfd_open(pid)
    except ProcessLookupError:
        return
    try:
        try:
            program = controller_path(pid)
            if program not in known_programs:
                raise RuntimeError(f"串口被其他程序占用，PID {pid}。请检查该进程。")
            print(f"正在正常停止 {program.name}（PID {pid}）", flush=True)
            signal.pidfd_send_signal(pidfd, signal.SIGINT)
        except (FileNotFoundError, ProcessLookupError):
            return
    finally:
        os.close(pidfd)


def main():
    if "--stop" in args and args != ["--stop"]:
        raise RuntimeError("--stop 需要单独使用")
    device = serial.resolve(strict=True)
    if not device.is_char_device():
        raise RuntimeError(f"串口设备不可用：{device}")
    owners = serial_owners(device)
    for pid in owners:
        stop_controller(pid)

    deadline = time.monotonic() + 8
    while remaining := serial_owners(device):
        if remaining - owners or time.monotonic() >= deadline:
            pids = ", ".join(map(str, sorted(remaining)))
            raise RuntimeError(f"串口仍被占用，PID {pids}。")
        time.sleep(0.15)

    print(f"串口已就绪：{device}", flush=True)
    if args != ["--stop"]:
        os.execv(sys.executable, [sys.executable, "-u", str(controller), "--full-range", *args])


try:
    main()
except (OSError, RuntimeError) as error:
    sys.exit(str(error))
PY
)" "$control_dir" "$@"
```
