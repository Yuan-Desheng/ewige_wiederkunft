> **团队负责人（Agent Harness 团队）岗位说明书**（2026-07-30 起草，工牌用）。
> 一句话：**定技术方向、守质量闸门、放大团队产能——让一群人用 AI 把软硬件项目一起干成，并让这条链路持续进化。**
> 与 [[Agent Harness 岗位职责]] 是「一层之隔」的关系：Agent Harness 对**单个项目**负总责，团队负责人对**技术方向、流程质量与团队整体产出**负总责。流程口径见 [[项目立项与研发流程规范]]。

## 一、工牌精简版（直接印在工牌背面）

> [!abstract] 团队负责人 · Agent Harness 团队
> **定位**：技术方向定调者 + 质量守闸人 + 团队产能放大器。
>
> 1. **定方向**——定 Harness 技术路线与软硬件技术栈，做模型与 Agent 产品选型。
> 2. **守闸门**——主持评审委员会，把住需求 / 交互 / 架构 / 交付四个 gate，不过不放行。
> 3. **带团队**——建单人全栈负责制的队伍，定标准、带教、评估，对人才梯队负责。
> 4. **交付软硬件**——用 AI 端到端推动软件与硬件（IoT / 数采 / 边缘）项目落地，对组合交付负责。
> 5. **做研究**——推进上下文管理、长期记忆、Multi-Agent、自进化 Agent、超长程任务等前沿，并建评测基准。
> 6. **建资产**——沉淀流程规范、Skill 库、知识库与 AI 机器人，让团队越跑越快。

*（工牌空间不足时，取 1 / 2 / 3 / 4 四条。）*

## 二、岗位定位

| 项 | 说明 |
|---|---|
| **岗位名称** | 团队负责人（Agent Harness 团队） |
| **一句话定位** | 对技术方向、交付质量与团队产能负总责的人 |
| **在流程中的角色** | 《项目立项与研发流程规范》中的 **评审委员会核心成员 / 召集人**，兼立项与定级的决策人 |
| **与 Agent Harness 岗的关系** | Agent Harness = 单项目 Owner（纵向打穿一个项目）；团队负责人 = 横向管方向、管标准、管人、管多项目组合 |
| **产能来源** | 自己也是一线 AI 开发者（不脱离代码），同时通过流程、工具链与人才梯队放大整个团队的产出 |

> [!important] 这个岗位不做什么
> 不当「只开会不动手的管理者」。**技术判断力必须来自一手实践**——自己也用 Agent 交付真实软硬件项目，否则评审沦为形式、选型脱离现实。

## 三、核心职责

### 3.1 团队建设与人才

- **建制**：按「单人全栈负责制」组建团队，明确每个项目的单一 Owner 与决策对口人。
- **招聘与定标**：定义 Agent Harness 等岗位的能力标准与面试口径，识别「对 Agent 有品味、能 0→1」的人。
- **带教**：把自己踩过的坑变成团队 SOP；对新人做 AI 开发工作流的实战带教，而非讲课。
- **评估与激励**：以「交付了多少可验收系统 + 让下一次交付快了多少」为考核主轴，而非代码行数或工时。
- **巴士因子对冲**：关键决策双人知晓；要求每个项目的知识库达到「另一个人能接手」的验收标准。

### 3.2 流程与质量守闸

- **主持评审委员会**：把住 **需求① / 交互② / 架构③ / 交付④** 四个 gate，三态结论（过 / 不过 / 有条件过），**交付评审必须显式通过**。
- **定级与分级**：判定项目是否达立项门槛、定项目级别，避免小项目走全套、大项目走捷径。
- **SLA 保障**：普通 gate 24h 内给结论，阻塞性问题即时响应——不让单人 Owner 空等。
- **维护流程规范**：以度量数据迭代《项目立项与研发流程规范》，砍掉形式化的环节，补上真出问题的环节。
- **守红线**：脱敏红线、测试硬门槛、安全闸（`/security-review`）——违反即打回，无例外。

### 3.3 技术方向与选型

- **Harness 技术路线**：定团队的 Agent 工作流骨架（Agent Loop、工具集、Subagent 分工、审批与安全边界、验证闭环）。
- **模型与产品选型**：持续评测主流模型与 Agent 产品（代码类 + 通用类），给出团队级选型建议与迁移节奏。
- **软硬件技术栈**：为软件（Web / 小程序 / 平台 / 后端）与硬件（嵌入式、IoT 数据采集、边缘计算、设备接入与协议）两侧定技术基线与复用组件。
- **过度设计的刹车**：对 AI 给出的「看着合理实则过度设计」的架构做最终裁决——小项目不许杀鸡用牛刀。

### 3.4 软硬件项目端到端交付

> [!tip] 技能范围：用 AI 开发各种软硬件项目（包括但不限于）
> 后端服务 / Web 与小程序 / 数据平台 / 桌面与 CLI 工具 / 嵌入式固件 / IoT 数据采集与设备接入 / 边缘侧推理 / 工业协议对接 / 仿真与可视化系统。**在没有直接经验的语言、框架、芯片平台上，也要能在 AI 辅助下做出有质量保证的东西。**

- **组合交付**：对同时在跑的多个项目负交付总责，做优先级与资源（含人、算力、设备）的取舍。
- **亲自下场**：高风险技术点自己做 spike 验证；关键项目的架构与安全设计亲自过。
- **跨软硬件协同**：软件侧与硬件侧的接口契约、联调节奏、现场验收由本岗位统筹。
- **对外交付承诺**：交付时间、范围与质量的最终承诺方。

### 3.5 Harness 研究与评测

- **前沿方向**：推动 **上下文管理、长期记忆、Subagent 与 Multi-Agent、自进化 Agent、超长程任务** 等方向的探索，并落到可运行原型上。
- **模型与 Harness 共进化**：与模型侧深度沟通合作，从 Harness 角度做深度适配，把模型能力变化第一时间转化为工作流升级。
- **评测基准**：提出 Harness 领域的基准测试与评测方法，构建评测数据、制定标注策略，用数据而非感觉判断「这套 Harness 是不是更好了」。
- **真实任务为反馈源**：以团队真实交付任务和多层面用户反馈作为研究输入，设计实验并持续迭代，避免自嗨式优化。
- **快速原型能力**：想法到可运行原型的转化速度，是本岗位研究能力的主要体现。

### 3.6 对外商务与组织资产

- **商务护城河**：变更管理的最终裁决人——大变更触发报价与工期调整，杜绝无限免费返工。
- **客户与合作方**：关键客户的技术对接与预期管理；重大承诺与 Owner 双人知晓。
- **组织资产沉淀**：Skill / 工作流库、项目知识库与 AI 机器人体系、模板与脚手架的建设与保鲜。
- **度量与复盘**：汇总团队级指标，主持复盘，把改进项回写规范，形成闭环。

## 四、任职要求

### 4.1 硬性要求

| 维度 | 要求 |
|---|---|
| **科研 / 工程品味** | 2 年以上计算机科学或相关领域科研 / 深度工程经验，水平过硬、眼界广阔、**有品味**；特别优秀者可放宽 |
| **学历** | 硕士及以上；特别优秀者可放宽 |
| **成果** | 计算机科学领域有含金量的科研成果或工程产出 |
| **0→1 能力** | 面对问题能独立分析、提出自己的 idea，从 0 到 1 推动研究与项目；**能快速把想法变成可运行原型**，实验迭代高效 |
| **AI 开发能力** | 熟练使用 AI Agent 工具做软件（及硬件配套软件）开发；学习能力极强，**在没有直接经验的语言 / 技术 / 框架 / 硬件平台上也能产出有质量保证的工作** |
| **Agent 重度用户** | 对 Agent Harness 的开发与研究有极大热情；深度使用过代码类与通用类 Agent 产品并融入工作生活；**对模型行为有品味、有判断力** |
| **技术原理** | 熟悉 LLM 与 Agent 机制：LLM API、KV Cache、Agent Loop、Tool Use、Reasoning、Planning、Skills、MCP、Memory、Subagent、Multi-Agent；对 **Prompt / Context / Harness Engineering** 有深入理解 |
| **软硬件视野** | 理解硬件项目的约束（供应链、打样周期、现场环境、协议与稳定性），能对软硬件一体方案做整体判断 |
| **沟通** | 良好的中文沟通能力；能与研究员、工程师、客户三类人有效对话 |

### 4.2 领导力要求

- **决策力**：信息不全时也能拍板，并对结果负责；不把决策踢给会议。
- **守闸的定力**：顶得住工期压力，不放行未过 gate 的东西——这是团队质量的最后一道防线。
- **放大而非替代**：让 Owner 有充分自主权，自己只在方向、风险、红线三处强介入。
- **诚实**：对内对外都如实同步进度与风险；不允许「AI 说跑通了」当成跑通了。

### 4.3 加分项

1. AI 领域相关科研经验，或 AI 行业研究员任职经历。
2. 个人开源作品，及开源社区的深度贡献。
3. 计算机科学、编程、数学或数据科学领域含金量高的竞赛奖项。
4. 硬件侧的一手经验（嵌入式 / 电子设计 / 工业现场部署）。
5. 其它超乎常人的、与本工作相关的才能。

## 五、考核指标

| 类别 | 指标 |
|---|---|
| **团队产出** | 团队季度交付项目数与按期率；人均可验收交付量 |
| **交付质量** | 各 gate 打回次数趋势；交付后客户缺陷数；安全高危项数（应为 0） |
| **流程健康度** | 评审 SLA 达成率；冻结后变更数与返工率的整体趋势 |
| **复利效应** | 沉淀并被复用的 Skill / 工作流数；同类项目二次交付的提速比例 |
| **人才** | Owner 独立带项目的人数；知识库「可接管」自检通过率；关键人员流失影响可控 |
| **前沿产出** | 研究方向的可运行原型数；评测基准建设进度；模型/产品选型决策的事后正确率 |

---

## 六、红线

> [!danger] 违反即视为管理事故
> - **放行未过 gate 的交付**（尤其交付评审沉默通过）。
> - **默许无限免费返工**：冻结后的重大变更不走变更管理。
> - **脱离一线**：对技术方向做决策却无一手实践支撑。
> - **公开仓库出现明文凭据 / 客户 PII**：团队负责人负连带责任。
> - **对上对下不诚实**：隐瞒延期、掩盖缺陷、以 AI 产出充当已验证结果。
