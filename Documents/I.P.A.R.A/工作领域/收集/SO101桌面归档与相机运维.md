> 用于复现SO101相机预览、查阅归档及恢复桌面常亮设置。来源项目：openRobotWholeMachine；Jetson、GNOME、GStreamer、LeRobot 0.4.4。笔记和附件不保存密码、私钥或打印机访问码。

## 一、原理

独立预览只打开相机，不连接机械臂串口；关闭画面或Ctrl+C后释放设备，才能交给遥操作/录制。训练数据包含视频、action、observation.state和元数据，单独的视频不能代替LeRobot数据集。当前任务与时间安排见 [[SO101双色双盘采集项目]]；更早环境快照见 [[SO-ARM101 LeRobot 部署与调试记录]]。

```text
图形桌面打开独立相机 → 调好并固定机位 → 退出独立预览
→ 本机桌面运行对应标签采集 → 完整抓放并回位松爪 → 手动结束
→ 等待保存/编码和正常退出 → 按meta映射核对视频与逐帧数据
```

11月9日桌面归档只移动12个相关文件，系统和BLG入口保留。原数据、虚拟环境、标定、代码和其他服务留在原位；相机预览进程未停止。

## 二、完整相机脚本与启动器

脚本位于 `/home/jzsd/Desktop/SO101项目/01_相机预览/SO101_camera_preview.sh`，完整内容如下：

```bash
#!/usr/bin/env bash
# SO101 camera-only preview, prepared 2026-11-07.
set -eu
if [[ -z "${DISPLAY:-}" ]]; then
  printf '%s\n' '请在 Jetson 的图形桌面终端中运行此脚本。'
  exit 1
fi
camera_device='/dev/video0'
stable_camera='/dev/v4l/by-id/usb-Generic_USB_HD_Camera_200910120001-video-index0'
if [[ -e "$stable_camera" ]]; then
  camera_device="$stable_camera"
fi
if [[ ! -e "$camera_device" ]]; then
  printf '%s\n' '未找到摄像头，请检查 USB 连接。'
  read -r -p '按回车关闭。' _ || true
  exit 1
fi
if fuser "$camera_device" >/dev/null 2>&1; then
  printf '%s\n' '摄像头正在被占用。请先关闭已有相机预览，或在原终端停止遥操作/录制，再重新打开。'
  read -r -p '按回车关闭。' _ || true
  exit 1
fi
printf '%s\n' 'SO101 独立相机预览：640×480，30fps。' '本程序仅使用摄像头，不控制机械臂，不录制训练数据。' '关闭画面窗口或在此终端按 Ctrl+C 可停止。'
exec /usr/bin/gst-launch-1.0 -e v4l2src "device=$camera_device" ! 'video/x-raw,format=YUY2,width=640,height=480,framerate=30/1' ! videoconvert ! ximagesink sync=false
```

同目录的 `SO101摄像头预览.desktop` 已修复Exec和Path，并验证为可信启动器：

```ini
[Desktop Entry]
Type=Application
Name=SO101 摄像头预览（仅相机）
Comment=640x480 30fps camera-only preview; no robot control
Exec=/bin/bash "/home/jzsd/Desktop/SO101项目/01_相机预览/SO101_camera_preview.sh"
Path=/home/jzsd/Desktop/SO101项目/01_相机预览
Icon=camera-web
Terminal=true
StartupNotify=false
Categories=AudioVideo;Video;
```

完整桌面文件副本在 [[Extras/机器人/SO101/2026-11-09/桌面文件/00_项目入口.txt|项目入口副本]] 所在目录。原 `A臂命令.txt` 是指向 `/data/so101/A臂命令.txt` 的软链接，搬移后目标保持不变；笔记附件中保存为可离线阅读的文本副本，原链接类型留在归档清单。

## 三、配置与只读查询

在Jetson图形桌面终端打开相机：

```bash
bash "/home/jzsd/Desktop/SO101项目/01_相机预览/SO101_camera_preview.sh"
```

SSH用于检查和文件整理；真实录制按任务要求在Jetson物理本机桌面执行。新终端先用已有环境，避免缺少CUDA动态库：

```bash
source /data/so101/env.sh
python -c 'import torch; print(torch.__version__, torch.version.cuda, torch.cuda.is_available())'
fuser -v /dev/video0 /dev/ttyACM0 /dev/ttyACM1
```

`/dev/video0`和`/dev/video1`属于同一相机，不作两只相机计数。稳定相机路径已写在上面的完整脚本；主从串口以 `/dev/serial/by-id/` 的现场映射和原环境为准。

### GNOME桌面常亮设置

11月9日发现会话空闲300秒，关闭空闲熄屏、调暗和自动挂起；保留锁屏功能，没有重启Jetson。下列是完整设置命令，作用于执行用户的GNOME配置：

```bash
export DBUS_SESSION_BUS_ADDRESS="unix:path=/run/user/$(id -u)/bus"
export GSETTINGS_BACKEND=dconf
gsettings set org.gnome.desktop.session idle-delay 'uint32 0'
gsettings set org.gnome.settings-daemon.plugins.power idle-dim false
gsettings set org.gnome.settings-daemon.plugins.power sleep-inactive-ac-type 'nothing'
gsettings set org.gnome.settings-daemon.plugins.power sleep-inactive-ac-timeout 0
gsettings set org.gnome.settings-daemon.plugins.power sleep-inactive-battery-type 'nothing'
gsettings set org.gnome.settings-daemon.plugins.power sleep-inactive-battery-timeout 0
gsettings get org.gnome.desktop.session idle-delay
gsettings get org.gnome.settings-daemon.plugins.power sleep-inactive-ac-type
```

结果已逐项读回；已存在的锁屏状态需要现场解锁一次。原设置备份和结果在 `/data/so101/outputs/desktop-power-settings-2026-11-09/`，副本见 [[Extras/机器人/SO101/2026-11-09/记录/桌面常亮设置.json|常亮设置记录]]。

## 五、踩坑记录

| 现象 | 已确认的原因或边界 | 处理与复核 |
| --- | --- | --- |
| 右键后采集退出 | 第二条0帧仍尝试保存；键盘事件可能跨保存阶段残留 | 已部署阶段隔离和空缓存保护；补丁及原代码备份保留 |
| 没按右键也不跟随 | 当时20秒自动结束后开始保存；退出另报夹爪6号过载 | 改为 `--dataset.episode_time_s=inf`；先卸载检查，避免持续夹死物体 |
| 直接导入Torch缺libcudss | 没加载已有so101动态库环境 | 先加载 `/data/so101/env.sh`，不临时重装Torch |
| 相机打开失败 | 独立预览或其他进程占用 | 先识别占用者；不为了抓图停掉机械臂控制程序 |
| 图像左右含义改变 | 相机从正视改到另一侧斜俯视，画面由蓝左红右变为红左蓝右 | 固定最终机位后统一任务标签，避免混用临时映射 |
| 文件夹归档后旧入口失效 | 原启动器写死Desktop根目录脚本路径 | 修复新Exec/Path，检查脚本语法和启动器信任状态 |

旧试录脚本中的 `a_test` 条数检查、单向任务标签及20秒/50条命令属于历史。尤其原命令含删除a_test的操作，仅保留追溯，不作当前采集入口。
