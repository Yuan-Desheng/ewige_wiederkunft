## 一、什么是工作流技能

- **定义**：一族封装好的 Claude Code Skill（多以「工作流-XXX」命名）。每个技能 = 一个有固定输入、固定阶段、固定产出的自主流程，用户给一句话（或一个文件）即可触发它跑完整段工作。
- **与开发规范的关系**：[[项目开发规范]] 讲「流程与评审」，本笔记讲「跑流程用的工具」。规范里每个研发阶段，背后就是这里的一个工作流技能。
- **触发方式**：自然语言点名（如「跑工作流-原型」）或对应触发词；技能自带 Plan/执行/自检阶段。

## 三、研发主链如何串起来

```text
可研/需求/任务书/PDF/xlsx
        │
   工作流-原型(req-to-proto)
        │  需求提取 + 功能定义 specs + 高保真 HTML 原型
        ▼
   工作流-设计(proto-to-design)
        │  架构/数据流/ER/接口/安全/运维 设计说明书
        ▼
   工作流-开发(design-to-code)
        │  可运行实现（后端+前端+库+一键启动）
        ▼
   工作流-测试(code-to-test)
        │  单元+接口测试 + 通过率报告
        ▼
   工作流-部署(app-to-deploy) / 工作流-打包(webapp-to-installer)
           可移植部署包 / Windows .exe
```
> 这条链 = [[项目开发规范]] 的执行引擎；`loop` 可把整条链「一路跑完 + 中断续跑」自动化。

## 四、真实实践（取自实际会话，已脱敏）

> 以下为同事项目里这些工作流的真实调用（路径/IP/端口已脱敏）。重点不是项目本身，而是**这些工作流到底接什么输入、怎么串、跑出什么**。

### 4.1 全链路实践（一条龙跑通）

> [!example] 案例 A · 广义储能协同规划平台（新疆科技项目）—— 原型→设计→开发→测试→打包 全链路
> - **原型**：`工作流-原型` 输入任务书 PDF +《新型电力系统广义储能协同规划平台》需求 docx（含电网拓扑、风光出力数据）→ 产出 33 个 HTML 页面 + `specs/` 功能定义 + `theme.js` 深浅主题 + 本地化 Tailwind/ECharts。
> - **设计**：`工作流-设计` 基于上面 33 页原型 + 原始需求 → 技术设计文档。
> - **开发 / 测试 / 打包**：`工作流-开发` → `工作流-测试` → 打包 exe。
> - **自动化**：用 `loop` 把「设计→开发→测试→打包exe 四阶段流水线一路跑完，并在用量限额中断后自动续跑」。
> - **要点**：纯静态前端也能走完整链路；`app-to-deploy` 也被用来给这套 33 页静态原型打可移植部署包。

> [!example] 案例 B · 四币种实时汇率转换系统 —— 原型→测试→打包 exe
> - **原型**：`工作流-原型` 输入需求 md（人民币/美元/越南盾/U币 双向汇率、走势、提醒、换算）→ 每个原型独立 HTML + 详细注释，覆盖用户端 + 管理端；可指定风格（此处要求「严肃、准确、简单大方」）。
> - **测试**：`工作流-测试` 对后端做接口测试 —— `target=api_health_rates type=api`，源文件 `main.py` → 生成 `test_api_health_rates.py`。
> - **打包**：`工作流-打包`（webapp-to-installer）把 Web 应用打成 Windows .exe（离线、桌面图标）。

### 4.2 原型工作流的「多源输入」实践（req-to-proto 用得最多）

`工作流-原型` 是全家族里调用最频繁的（10+ 次）。真实输入源五花八门，说明它对输入格式很宽容：

- **思维导图 PDF** → 能碳管理平台原型（要求高保真、高端大气、交互炫酷）
- **采购计划 xlsx** → 提取功能需求 → 城乡垃圾流向监测平台 + 智慧环卫系统原型
- **答辩 docx** → 零碳园区多主体协同治理原型
- **可研 + 需求 + 设计方案（多文件）** → 浙江虚拟电厂仿真原型（要求体现「融合大模型智能体」创新点）
- **已结构化需求包** → VPP「仿真预测」模块原型（需求已拍板，跳过需求访谈直接出原型）
- **参考风格目录** → 可传入「参考 HTML 风格目录」让新原型对齐既有视觉

### 4.3 把通用工作流「fork 成项目专用工作流」（重要洞察）

> [!tip] VPP server 项目把通用工作流沉淀成了一套 `vpp-*` 专用技能
> - `vpp-req-to-change`（需求变更，带 `changeId`）→ `vpp-design` → `vpp-design-to-code` → `vpp-dev-integrate`（同一 `changeId=add-vpp-command-dashboard` 串起一次完整需求变更）。
> - `vpp-proto-to-design`（`protoDir=...prototypeV6`）、`vpp-feature-pipeline`（增量开发功能模块：需求规格 + 参考原型 → 重建模块）。
> - `vpp-metric-sql-backfill` —— **被调用 33 次**，是该项目最高频工作流：基于数仓表（`dwd_user_elec_15min_v1`、`dwd_adjustable_capacity` 等）按「行业+省+市+区县+时间点」维度算实时负荷/用电量/环比/峰谷差/可调能力等指标，产出「取数 SQL + 验数 SQL + 补数脚本」。
>
> **洞察**：通用工作流（req→design→code→...）可以按项目沉淀成带项目术语、带数仓表、带 `changeId` 流转的**专用工作流** —— 这正好印证 [[项目开发规范]] 里「每个项目配一套自己的工作流 / AI 机器人」的主张。

### 4.4 文档 / 研究 / 测评类实践

- **科技可研**：`工作流-科技可研` 写《负荷侧虚拟电厂实时感知与电碳协同智能调控》2027 科技项目可研，以已定稿储备简表为内容来源、对标浙江电网可研模板。
- **答辩 PPT**：`工作流-答辩PPT` 输入「电碳协同发展基础理论」可研 doc → 答辩级 PPT。
- **软件测评**：`工作流-测评`（rusp-quality-eval）对某端口运行的程序做 GB/T 25000.51 测评。
- **深度研究**：`deep-research` 做地平线机器人（9660.HK）估值与走势研判、核查「绿电直供算力中心」真实落地情况。
- **选股估值**：`工作流-选股`（stock-growth-valuation）跑英伟达 NVDA、明略科技 02718、供销大集 000564。

### 4.5 编排 / 自动化实践

- **`loop` 自动续跑**：把多阶段流水线「一路跑完 + 限额中断后自动续跑」；也用于定时同步另一会话的进度（抓屏对比、简要汇报）。
- **`update-config` 自动留痕**：加 Stop hook —— 每轮结束检查工作流产物目录（`prototype/ design/ app/ tech/`）有无改动，有则自动 `git pull --rebase --autostash` + add + commit + push。把「工作流产物」纳入自动版本管理。

## 五、经验提炼（对照开发规范）

> [!summary] 实践验证了开发规范的哪些点
> - **原型驱动可落地**：`工作流-原型` 能吃 PDF/xlsx/docx/md 多种原始材料，直接产出高保真可交互原型 —— 印证规范「先原型、低成本收敛需求」。
> - **全链路可自动化**：原型→设计→开发→测试→打包能用 `loop` 串成一条龙并自动续跑 —— 单人负责制下，AI 工作流确实能补齐工种。
> - **工作流可 per-project 定制**：VPP 把通用工作流 fork 成 `vpp-*` —— 印证规范「每项目配专用工作流 / AI 机器人」。
> - **产物要纳管**：Stop hook 自动提交工作流产物 —— 对应规范「各阶段产出物入知识库」。

> [!warning] 用的时候注意
> - 工作流产物（尤其 AI 生成代码 / SQL）仍要**人工必检**（见规范 §五各阶段），别盲信。
> - 涉及内网地址 / 凭据 / 真实数据时先脱敏，工作流产物入公开库前自查。
> - 大任务用 `loop` 续跑前，先确认产物目录与提交策略（参考 4.5 的 Stop hook）。
